# 模块 10B：受控多 Agent 对照实验

> 本课只运行离线、确定性夹具。它不启动真实 Codex、Claude Code、子代理、模型 API 或本地工作树，也不把固定教学数字伪装成账户实际时间、Token 或账单。

## 你要解决的真实问题

同一份“设备遥测与报告工具”任务已经能够由一个 Coding Agent 完成。团队接着提出“再开两个子代理会更快”的建议，却没有先回答四件基本问题：每个子代理到底拥有什么任务边界？哪些信息需要共享？谁负责汇合和最终验证？冲突、额外使用量和验证成本是否抵消了并行收益？

本课的目标不是证明多 Agent 更先进，而是让你能根据同一验收目标的证据做决定。完成后，你应能：

1. 把单 Agent 与子代理路径锁在相同的目标、输入契约和验收条件上。
2. 写清子任务边界、共享上下文、汇合点和最终责任人，避免多个工作者默认写同一输出。
3. 同时比较墙钟时间、使用单位、验证单位、冲突和恢复成本，而不只看“子代理数量”。
4. 在冲突恢复后仍能合理得出“不采用多 Agent，保留单 Agent 基线”的结论。
5. 导出并让本地 checker 重新推导匿名 evidence；页面完成状态本身不算成果。

## 心智模型：并行是有前提的编排选择

把多 Agent 当成一种编排选择，而不是质量保证：

```text
共同目标与验收
       │
单 Agent 基线 ──┐
               ├─ 比较：墙钟时间 / 使用量 / 验证成本 / 结果质量
子任务边界 ────┤
共享上下文 ────┤
汇合与验证 ────┤
冲突与恢复 ────┘
       │
采用有边界的并行，或继续使用单 Agent
```

这里有几个不能省略的边界：

| 项 | 必须说明什么 | 常见错误 |
| --- | --- | --- |
| 同一目标 | 两条路径都通过同一组验收条件 | 单 Agent 做完整任务，子代理只做搜索，就比较“快慢” |
| 子任务边界 | 每名子代理的唯一产物或只读责任 | 两个子代理默认拥有同一个报告文件 |
| 共享上下文 | 只共享目标、输入契约和验收约束 | 把全部日志、推理过程或无关历史广播给所有工作者 |
| 汇合点 | 谁整合结果、谁跑最后验证、失败由谁升级 | 主协调者直接相信子代理的“完成”说明 |
| 成本 | 墙钟时间、使用量、协调/验证工作 | 只报告更短的墙钟时间，忽略额外调用和复核 |
| 结论 | 采用、继续比较或不采用，并说明条件 | 把“已经并行”误写成“已经更好” |

## 操作前预测

在运行夹具前，写下你的预测：

- 三个只读、职责不重叠的复核任务是否可能降低墙钟时间？即使是，也会不会增加使用和验证成本？
- 两个子代理同时拥有 `report-summary` 的写入边界时，你预期冲突在哪里出现？
- 把 `report-summary` 拆成两个唯一边界并重新验证后，恢复成功是否自动意味着应该采用多 Agent？
- 若你没有真实工具的计费/时间数据，怎样避免把模拟器数字误写进交付报告？

## 主工具演示：产品适配层只解释能力边界

Codex 和 Claude Code 都提供子代理/并行工作的产品能力，但它们不是同一个抽象层，也不保证同样的配置、默认值或成本表现。

- [Codex Subagents（OpenAI 官方文档）](https://learn.chatgpt.com/docs/agent-configuration/subagents) 说明了专门化 Agent 的并行委派、汇总、上下文隔离与成本边界。文档也明确提醒：每个子代理都会进行自己的模型和工具工作，因此相对可比的单 Agent 路径会消耗更多 Token；对写入密集的并行工作应格外小心冲突和协调开销。
- [Run agents in parallel（Claude Code 官方文档）](https://code.claude.com/docs/en/agents) 区分了 subagents、agent view、agent teams、动态工作流与 worktrees。它将 worktree 定位为隔离并发编辑的手段，并说明 agent teams 是实验性、默认关闭的功能；多会话/子代理并行会放大 Token 使用。

这些是工具适配层事实。本课的共同验收目标、固定夹具、成本单位、故障恢复顺序和“不采用多 Agent”结论属于课程原创设计，不会从真实客户端界面或账户数据推断出来。

## 本地实验：同一目标的两种子代理情形

<MultiAgentLab />

按这个顺序操作：

1. 先运行“边界清晰的并行复核”，确认单 Agent 与子代理都通过 `telemetry-report-v2` 的四项验收。
2. 读出三个唯一任务边界、最小共享上下文和 `coordinator-verifies` 汇合点；比较两条路径的墙钟时间、使用单位和验证单位。
3. 记录该对照。它只能说明“可继续在独立、只读或不重叠任务中比较”，不能默认推广到写入任务。
4. 再运行“故意重叠写入并恢复”。观察两个子代理同时拥有 `report-summary`，记录 `shared-output-collision`。
5. 记录恢复：协调者将责任重新分区，再跑原来的同一验收。即使最终结果通过，本夹具仍给出 `do-not-adopt`，因为墙钟时间、使用和验证成本都上升。

导出 JSON 后，在 Windows 11 + PowerShell 7 中运行本地检查：

```powershell
Set-Location -LiteralPath .\checker
python -m course_check check t22-multi-agent --root .. --evidence-file ..\t22-multi-agent-evidence.json --output ..\t22-multi-agent-checked.json --json
Get-Content -LiteralPath ..\t22-multi-agent-checked.json
```

没有 `--evidence-file` 时，checker 只检查页面、模拟器、lab README 和来源账本，结果是 `partial`。有 evidence 时，checker 会根据稳定场景重新推导检查项；它不信任手写的通过结论、时间、使用单位、冲突或恢复状态。

## 故障注入与恢复：共享写入并不因“Agent 更多”而消失

“故意重叠写入并恢复”不是为了训练你合并冲突命令，而是为了练习更早的编排恢复：

1. **停在汇合点。** 不接受两个子代理各自声称成功；先把 `shared-output-collision` 记录为冲突。
2. **回到边界。** 把重复的 `report-summary` 拆成不重叠的摘要大纲和指标表，明确谁拥有哪一个输出。
3. **缩小共享上下文。** 只把目标、输入契约、验收条件和必要的汇合摘要交给后续工作者，不广播原始日志、私有数据或无关会话历史。
4. **重新运行同一验收。** 不因为“恢复过程很复杂”而降低要求；输出、单位和验证仍必须与单 Agent 基线一致。
5. **重新算账并决定。** 若冲突恢复后仍增加墙钟时间、使用量和验证工作，则选择 `do-not-adopt` 是有效、可交付的实验结论，而不是失败。

真实项目中还应在开始写入前创建 Git 基线、使用独立 worktree 或明确目录所有权，并由人决定何时批准合并。不要在生产仓库用本页面的固定数字替代一次真实、带审批的测量。

## 迁移挑战：用一件真实但低风险的任务做小型对照

任选可用的 Codex 或 Claude Code，在一次性练习仓库中设计一个低风险任务。不要在真实研究或企业仓库直接并行写入。

- 先用单 Agent 完成一轮，保留目标、验收、diff 和本地测试证据。
- 只把互不重叠的只读探索、测试日志归类或文档索引拆给子代理；写入任务先保留一个所有者。
- 为每个子代理记录边界、共享上下文、汇合点、权限和退出条件；若工具支持 worktree，先确认当前客户端的隔离语义。
- 比较相同验收下的墙钟时间、模型/订阅用量和人工验证时间。真实账单、Prompt、源码和路径不要导入本课 anonymous evidence。
- 至少设计一次重叠边界的预演：不启动额外写入者，而是写下“如果两个工作者改同一文件，谁停、谁重新分区、谁重新验证”。若收益不抵成本，结论写为“不采用”。

## 可核验成果：匿名对照 evidence

至少保留：

- 一条边界清晰的并行复核记录和一条重叠写入冲突/恢复记录；
- 相同 `telemetry-report-v2` 目标和四项验收条件的对照；
- 每个子代理的责任边界、最小共享上下文、汇合点、冲突和恢复动作；
- 同时显示墙钟时间、使用单位和验证单位的成本比较；
- 包含 `do-not-adopt` 的结论以及 `t22-multi-agent-evidence.json`、checker 输出；
- 一份不包含真实 Token/账单、路径、源码、模型输出、密钥或个人数据的迁移挑战说明。

checker 的通过项是 `same-goal-compared`、`task-boundaries-declared`、`time-usage-verification-compared`、`conflict-recovered`、`decision-supported` 和 `offline-deterministic`。它验证固定课程夹具和匿名证据边界，**未验证**任何真实 Codex/Claude Code 子代理、worktree、账户计费或模型质量。

## 风险、版本与来源卡片

- **账号与成本**：离线夹具、checker、Node 和浏览器测试免费，不需要账号、API key、模型额度或网络。真实产品子代理可能消耗额外 Token、订阅额度或 API 预算；本课不要求、也没有执行真实调用。
- **权限与副作用**：页面只处理内置确定性对象。不会启动线程、进程、worktree、模型、MCP、文件写入或网络。浏览器下载和 checker 输出都由学习者显式触发。

- **事实与课程判断**：官方文档支持子代理、并行、上下文隔离、worktree/协调和额外用量的产品事实。共同验收、固定成本单位、冲突夹具、恢复序列、结论规则和“不采用”判断是本课程原创实验设计。
