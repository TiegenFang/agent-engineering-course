# 模块 5B：压缩、恢复与交接

> 本课的主实验是浏览器内的确定性 context fixture。它解释压缩失真、约束遗漏、污染恢复和交接边界，不伪装成真实 Codex、Claude Code、模型或 API 调用。

## 你要解决的真实问题

长任务中，当前上下文不可能无限增长。压缩可以减少工作集，但“更短”不等于“保真”：一条只读约束可能被改写，一条不外发约束可能消失，上一轮历史也可能被误当作当前指令。另一个会话接手时，如果只说“继续做”，它无法知道目标、已经验证的证据、剩余风险和下一步。

完成本课后，你应能：

- 用同一合成任务比较压缩前和压缩后的结果，识别失真与约束遗漏，而不是只看摘要长度。
- 把不可信备注当数据，观察污染任务的失败证据，并按检测、隔离、恢复、复核顺序恢复工作集。
- 创建包含目标、状态、证据、风险和下一步的跨会话交接包。
- 明确区分 **上下文（Context）**、**历史（History）** 和 **Memory**：当前工作集、会话记录和有所有者/寿命的长期知识不是同一个容器。
- 导出不包含聊天正文、路径、密钥、原始遥测或个人信息的匿名 `evidence` JSON。

## 心智模型：压缩是有损变换，交接是显式合同

把工作状态分成三个层次：

| 层次 | 它回答什么问题 | 本课的边界 |
| --- | --- | --- |
| 上下文（Context） | 当前这一步做决定需要什么？ | 目标、约束、工具结果、可核查证据组成工作集；容量有限，会被选择和压缩。 |
| 历史（History） | 之前发生过什么？ | 可回看、可总结，但不会因为出现在记录里就自动获得指令权限。 |
| Memory | 什么知识值得跨会话保留？ | 需要所有者、来源、寿命和删除条件；不是聊天全文，也不是压缩后的默认垃圾桶。 |

压缩前后必须分别留下可观察结果。**保真压缩**保留目标、三条约束和证据；**压缩失真**改变证据约束；**约束遗漏**丢掉“不外发”约束。恢复不是“再总结一次”，而是从可核查基线重新装配工作集，并重新验证边界。

## 操作前预测

在每种压缩模式运行前，先选择一个预测并点击“记录预测”：

1. 压缩后仍保留目标、约束和证据；
2. 压缩会改变或遗漏至少一条约束；或
3. 历史会自动变成长期 Memory。

预测错误不会删掉实验，但会留下失败的预测记录。切换模式后必须重新预测；这样“我事后知道答案”不能替代运行前的判断。

## 本地实验：导出匿名 evidence

在页面点击“导出匿名 evidence”，把文件保存到课程工作区之外的临时位置，再用 Windows 11 + PowerShell 7 的本地 checker 检查：

```powershell
python -m course_check check t15-context-recovery --root .. --evidence-file ..\t15-context-recovery-evidence.json --output ..\t15-context-recovery-checked.json --json
```

不带 `--evidence-file` 时，检查器只确认页面、模拟器和实验合同存在，结果会是 `partial`。带证据文件时，它会验证三种压缩模式的顺序无关结果、污染恢复、交接字段和三层边界；它不会把任务正文复制到网页交换文档。

## 故障注入与恢复

### 压缩失真

“压缩失真”模式会把 `preserve-evidence` 约束改写。它不是一个可以凭感觉接受的“近似成功”，而是一个必须被诊断的失败结果。恢复动作是回看压缩前工作集，找出改变的约束，再生成一份新的压缩结果。

### 约束遗漏

“约束遗漏”模式会删除 `no-network` 约束。如果交接包只保留“报告已经准备好”，下一会话可能误以为可以外发或访问网络。恢复动作是从基线重新补回约束，并在交接中写出风险，不要把历史中的一句建议提升为当前权限。

### 污染任务

点击“注入污染任务”后，固定的不可信备注会试图把只读任务改成外发/删除任务。它只是上下文中的数据，不是规则。按 `detect → quarantine → restore → revalidate` 依次点击“隔离并恢复”，再确认三条约束已经回到工作集。页面不会执行备注里的危险动作，也不会调用真实工具。

## 跨会话交接包

交接不是把整段聊天复制给下一个会话，而是一个小而明确的合同：

| 字段 | 作用 |
| --- | --- |
| `goal` | 说明接手者要完成的任务，不写“继续上一轮”这种空目标。 |
| `status` | 区分 `ready-for-next-session` 和仍有阻塞的 `blocked`。 |
| `evidence` | 只列稳定证据 ID，说明哪些压缩和恢复步骤真的发生过。 |
| `risks` | 写出压缩有损、历史权限和 Memory 晋升等剩余风险。 |
| `next_steps` | 给新会话一个可执行的下一步和复核点。 |

交接包还固定标注 `context`、`history`、`memory` 三层。它不包含聊天全文、原始遥测、绝对路径、密钥或个人信息。完成三种压缩对照和污染恢复后点击“生成交接包”；状态为 `ready-for-next-session` 才能交给另一个会话或工具。

## 迁移挑战：换工具，保留边界

可以把匿名交接包带到你可用的 Codex 或 Claude Code 会话中，请它只根据 `goal`、`status`、证据 ID、风险和下一步说明“如何继续”。要求它先复述三条约束，再指出哪些信息属于当前 Context、哪些只是 History、哪些不能未经审批写入 Memory。不要声称本页已经完成真实工具的压缩或会话恢复验收；本页只验证厂商无关的方法和稳定证据契约。

## 可核验成果：匿名 evidence

检查器需要以下固定证据：压缩前后对照、压缩失真诊断、约束遗漏诊断、污染任务恢复、完整交接字段，以及上下文/历史/Memory 区分。页面导出的 `evidence` 只包含这些 ID 的 `passed`/`failed` 状态；`experiment` 只保留模式、结果枚举、布尔诊断和交接字段数组。

## 风险、版本与来源卡片

- **账号与成本**：确定性页面和本地 checker 免费；不需要 Codex、Claude Code、模型/API 账号，也不会产生 Token 或 API 费用。迁移挑战若在真实工具中执行，账号、模型、费用和产品权限由该工具单独承担，需人工确认。
- **权限与副作用**：页面只在浏览器内处理固定合成字符串；不读写仓库、不执行命令、不访问网络、不触碰设备。下载和导入 evidence 是学员主动操作。
- **隐私边界**：不要把真实研究记录、个人信息、密钥、路径或聊天全文粘贴到实验。导出 JSON 只保留状态和稳定 ID，但下载文件仍由学员负责保管。
- **失败与恢复**：压缩失真和约束遗漏必须被识别；污染任务必须完成隔离、恢复和复核；交接缺少任一必填字段时保持 `blocked`，补齐后再生成。
- **版本与验证边界**：确定性实验合同 v1 和 `agent-engineering-course/evidence` v1 锁定课程版本 `0.1.0-alpha`，页面/Node/Python/Playwright 测试不调用真实模型。本课未验证真实 Codex、Claude Code 压缩策略、跨会话产品状态或跨平台浏览器行为。
- **官方事实核验**：OpenAI 的 `Compaction` 指南描述 API 层的上下文压缩机制，Anthropic 的 `Context window` 与 `Checkpointing` 文档描述 Claude Code 的上下文窗口和回退/检查点语境；这些是截至 **2026-08-13** 的产品事实，不是所有 Agent 的统一标准。课程方法和本地 fixture 为原创设计。
