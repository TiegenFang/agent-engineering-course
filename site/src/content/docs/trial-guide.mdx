# 试学指南与观察表

本页是课程试学审计（issue T12）的完整材料包。试学目标不是收集满意度，而是记录真实阻塞点、操作观察和可核验结果，用于在正式推广前定位课程的问题。

## 招募画像

邀请 8–12 名代表性初学者，尽量覆盖以下三个维度：

| 维度 | 覆盖要求 |
| --- | --- |
| 背景 | 科研背景与企业背景各有代表 |
| Git 习惯 | 有稳定 Git 习惯与没有稳定 Git 习惯的学员都要有 |
| 工具访问条件 | 仅能用 Codex、仅能用 Claude Code、两者都可用三种条件都要覆盖 |

试学使用的课程版本、日期和学员条件必须记录在观察表头部。

## 试学任务

三项任务与 Alpha 指标一一对应。学员按顺序完成，允许在任一任务停止——停止点本身就是有效的审计数据。

### 任务一：环境基线（模块 0）

1. 按[环境诊断学习旅程](/module-0-environment/)运行只读诊断脚本，得到 `environment-diagnostic.json`。
2. 在 `checker` 目录运行 `python -m course_check check t05-environment ...` 得到匿名 evidence JSON。
3. 把 evidence 导入课程首页，确认形成本地完成状态。

**通过证据**：导入成功的 environment evidence；记录完成用时与每一步的阻塞点。

### 任务二：首个可核验成果（模块 1–3，按工具条件选路径）

- 仅 Codex：完成[模块 3 的 Codex 安全仓库任务](/module-3-codex-task/)。
- 仅 Claude Code：完成[模块 3 的 Claude Code 迁移挑战](/module-3-claude-migration/)（以压力变化输入路径替代 Codex 主实验）。
- 双工具：完成 Codex 主实验后再做迁移挑战。

**通过证据**：对应课节的 checker evidence；记录 Agent 实际行为与课节描述的偏差。

### 任务三：双工具迁移挑战（模块 3）

对已完成的任务，换另一工具重复一次变化输入的版本。观察学员是否能复用同一能力目标，而不是重新摸索。

**通过证据**：第二条 evidence 与学员对「概念相同处、操作差异」的口头或书面总结。

## Alpha 指标

| 指标 | 目标 |
| --- | --- |
| 完成任务一（环境基线） | ≥ 80% 学员 |
| 完成任务二（首个可核验成果） | ≥ 70% 学员 |
| 完成任务三（双工具迁移挑战） | ≥ 60% 学员 |
| 关键安全问题（密钥泄漏、不可恢复操作、失效命令） | 0 起 |

未达标的项目不得解释为「学员问题」，须回溯到课节设计并列入改进清单。

## 已知边界

- 本课程版本（1.0.0）的自动化门槛全部通过：检查器、内容契约、构建与桌面/390px 移动端浏览器契约、无障碍静态审计、发布安全审计。
- 现场人工验收尚未由真人执行：真实 Codex/Claude Code/MCP/付费 API 行为、macOS 或 Linux 路径、读屏与键盘完整人工复核在课节中标注为未验证；试学中的真实工具行为即是对这些边界的第一手补充证据，出现与课节描述不符时请在观察表中记录。
- 观察表包含学员工作环境信息，回收时只提交匿名版本；不要把密钥、真实研究数据或企业数据写进任何记录。

## 结果回收

观察表以匿名文本形式提交到仓库 [Issues](https://github.com/TiegenFang/agent-engineering-course/issues)，标题注明「试学审计-学员编号」。维护者汇总后更新试学审计报告，并锁定改进清单。
