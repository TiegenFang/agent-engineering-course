# W2 · 与模型对话的正确姿势

本课不需要安装任何东西，全程在浏览器里完成。读完正文、做完两轮改写练习并自评，本课就算完成——结果保存在你自己的浏览器里。

## 一分钟版结论

模型只会顺着你说的话往下接：你说得模糊，它就把模糊的地方替你「猜」着补齐；你把话说清楚，它才可能一次做到位。把模糊请求改写清楚，最小版本只需要补齐四个要素：

- **目标**：你要什么交付物，先说清它长什么样、给谁用。
- **上下文**：这件事的背景、读者是谁、数据从哪来——模型不知道的部分都要给。
- **约束**：只许做什么、不许做什么、范围和篇幅怎么限制。
- **验收标准**：你怎么判断「做好了」，给出可以逐条检查的证据。

## 两个生活化对照

**例一：改一段话。**

- 模糊版：「帮我把这段发给物业的话改一下。」
- 结构化版：「请把这段话改成 200 字以内的正式报修函（目标）。收件人是物业客服，事实是单元门禁坏了三周、此前已报修过两次（上下文）。只改措辞和结构，不添加、不改动任何事实，语气正式但不指责（约束）。我会检查：读信人 10 秒内能找到报修时间和诉求，末尾有明确的处理期限请求（验收标准）。」

**例二：安排一次出行。**

- 模糊版：「帮我看看周末去哪玩。」
- 结构化版：「请给我一份两天一夜的周边游方案（目标）。四个人同行，其中两位是 70 岁老人，从市区出发车程不超过 2 小时（上下文）。每天步行总量控制在 3 公里内，给出总预算区间，不安排需要爬山的景点（约束）。我会核对：每个推荐地点都标明营业时间和是否需要预约，两天的时段安排没有冲突（验收标准）。」

两种说法花的时间差不多，但第二种把模型的「猜测空间」挤掉了一大半。这不是话术技巧，而是把验收标准前置到了提问里——W1 讲过，Agent 靠「观察结果」推进任务，你能说清「什么算做好」，它就能自己朝那个方向收敛。

## 什么时候值得花这个功夫

- 一次就要到位的任务（要交付、要复核的输出）值得先写四要素；随手问问的概念问题不必过度包装。
- 四要素不是四种格式，一句话顺带交代也算；先有「补齐信息」的意识，再谈模板。
- 本课教的是最小版本。完整的 Agent 指令工程还包括非目标、工具边界、输出契约、失败证据等要素，那是核心线 [模块 2：Agent 指令工程](/module-2-agent-instruction/) 的内容，先完成本课再去会顺畅很多。
