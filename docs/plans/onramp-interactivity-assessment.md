## 一、先给结论（修正版）

v2 的**骨架已落地**（四课正文 + 四个交互组件 + BYO-key 实验 + 案例库 + 进度向导，均已随 v2.0.0 发布）。但「可交互教程」这个目标，**最多算完成了三分之一**。问题不在缺内容，而在三件事：

1. **招牌时刻对零基础是断的**——W3 的真实调用是整套 v2 的卖点，却同时被「账户 + 绑卡 + 建密钥」这道外部门槛挡住；离线兜底又是一段预制玩笑串，既不是证据、也不教东西。真正零基础的人走到 W3 会卡住或跳过。
2. **四个交互里只有一个有真反馈**——W1 是 3 道可猜的选择题，W2 靠单选框自证，W4 是承诺勾选。它们给的是「完成感」，不是「反馈」。这更像四张自评表单，不是交互教程。
3. **完成状态既不闭环、也不诚实**——W3 完全不落盘；W2 闭眼勾选也算完成；三处硬编码同一个 `localStorage` 键却无共享模块。更关键的是「动作 = 完成」这个判定本身很弱：发一次默认消息、勾两个框，就能被记成「已理解」。

| 上一版的问题 | 为什么错 | 修正 |

## 三、逐课批判评估（对照 v2 规格 W1–W4 表）

| 课节 | 组件 | 完成状态 | 真反馈 | 主要问题 |
| --- | --- | --- | --- | --- |
| W1 什么是 Agent | `StartQuiz` | ✅ 写 `start-1` | ❌ 3 道可猜单选，答错只给解释不给重做 | 一次性、答案就在课文里，闭眼也能碰对 |
| W2 与模型对话 | `DialogueRewrite` | ✅ 写 `start-2` | ❌ 单选框「我覆盖了全部四要素」 | 不写不改也能勾选完成；自证形同虚设 |
| W3 API key 真实调用 | `ByoKeyChat` | ❌ **零落盘** | ⚠️ 唯一真往返，但离线兜底是预制串 | 真实调用需账户+绑卡；成功不落证据；错误提示有行话（「速率限制或额度不足」） |
| W4 网页到终端 | `TerminalBridge` | ✅ 写 `start-4` | ❌ 6 项自评，含「我愿意每周投入 2–3 小时」 | 把「理解」与「意愿」混为一谈；「起步章完成」不校验 W1–W3 |

规格自违背的具体证据：v2 规格 W3 的 Verification 列为「Browser state + live call record」。实现中 `ByoKeyChat.astro` 全文件无任何 `localStorage` 写入，调用成功后端点/token/耗时只显示在屏、刷新即失。两项承诺全部落空。

## 四、七个关键差距（按「对初学者的伤害」排序）

1. **招牌时刻被门槛挡住（最严重）**。零基础学员没有 API 账户；W3 的真实调用需要「注册 → 绑定支付方式 → 生成密钥 → 授权模型」这一串外部流程，课程没有手把手引导。课程自己承诺「W1–W4 零成本可完成」，代价就是把最亮的「第一次真实调用」降级成离线预制串。免费路径和招牌路径是同一条路的两个岔口，但岔口处没有指路牌。

2. **交互不等于反馈**。W1/W2/W4 是「自评表单」，唯一有真实往返的是 W3。AGENTS.md 内容契约里「操作前预测 → 方向提示 → 诊断提示 → 检查证据 → 带解释参考实现」的分层支持，起步章基本只落到最后一层（给参考）。没有任何一课在动手前让学员**先预测**。

3. **完成判定偏弱、可作弊**。W2 不写不改也能勾选完成；W3「发送一次」即完成的语义，会让发默认消息看预制串的人也被记为「已理解」。动作 ≠ 理解，对初学者尤其危险——他会带着「我学会了」的错觉进入进阶线。

4. **三处硬编码 `course-start-progress` 无共享模块**（`StartQuiz.astro:88`、`DialogueRewrite.astro:93`、`TerminalBridge.astro:54`），键名散落、无聚合、无导出。改一处即碎。

5. **错误提示有行话**。`ByoKeyChat.astro:173-181` 的 429 提示是「速率限制或额度不足」，对零基础是新的阅读障碍；他需要的不是术语，是「你请求太快或账户没钱了，怎么办」。

6. **首页目录缺 W2/W4**。`CourseShell.astro:17-20` 的「网页端起步章」只链 W1、W3，与规格表自身的四课结构自相矛盾，W2/W4 从首页不可达。

7. **移动端与恐惧感未处理**。BYO-key 在手机浏览器的 fetch/CORS 行为未验证；「公共电脑勿用」「密钥在开发者工具可见」是正确提醒，但对零基础可能只留下「很危险」的恐惧，缺一句「你的密钥随时可在控制台撤销，错了能重来」的安全感。

## 五、重写后的北极星（判断所有改动的标尺）

> 一个从未碰过终端和 API 的人，能**在不看答案的情况下**：说出模型与 Agent 的区别；写出一条四要素指令；看懂一次真实调用里「线上发生了什么」；并明确知道自己下一步去哪。

所有改进只服务这一句。完成记录、聚合进度、首页目录，都是为它服务的脚手架，不是目的本身。

## 六、改进计划（重排优先级）

### P0 · 让招牌主线在免费路径也成立

- **A1 · 离线演示升级为「真实样例 + 逐段注释」**：把 `ByoKeyChat` 的离线预制串（`ByoKeyChat.astro:78-85`）换成一份**真实记录过的**请求/响应样例——真实 JSON 形状、真实 header、真实 token 数、真实耗时，逐段标注「这一步在干什么」。明确标「这是已记录的样例，不是此刻发出」。这样没密钥的人也能看见线上到底发生什么，兑现「证据先行」。
- **A2 · 给「没密钥」的人一条不堵死的路**：W3 明确给出「以后再来做真实调用」的占位与回跳，而不是让没有密钥的人走到死胡同；在隐私说明旁补一句「密钥错了能撤销、随时能重来」。
- **A3（需维护者拍板）· 是否把「创建 API 账户」做成 W3 的可选引导**：外部链接 + 普通话分步骤。这是零基础最大的隐性门槛，但涉及指向第三方账户页，是否纳入课程正文由维护者决定。

### P1 · 把「自评表单」改成「有反馈的练习」

- **B1 · 每课交互前加「操作前预测」**（内容契约精神）：W3 发送前先预测「请求会到哪个端点 / 大约多少 token / 第一次会成功吗」；W2 改写前先预测「漏掉哪一要素会导致模型乱猜」。预测题本身作为理解检查点，答错给出为什么。
- **B2 · W2 自证改成「引用式」**：把单选框拆成目标/上下文/约束/验收标准四要素，且每项要求学员**从自己写的文字里指出这一要素落在哪一句**（引用式自证），而不是勾一个「我覆盖了全部」。不做文本启发式判分——对初学者，误判比不判更糟。
- **B3 · W1 支持重做 + 错题回顾**：现在答错只给解释不给重做，补「重做」与错题解释回顾。
- **B4 · 错误提示改普通话**：429 等术语翻译成「你请求太快或账户额度用完，稍后再试或查账户」，并附一句「失败本身也是实验数据」的引导（把故障注入转成教学点）。

### P2 · 补闭环 + 聚合进度（上一版的 P0，降级但仍必要）

- **C1 · 抽一个共享进度模块**：消除三处硬编码 `course-start-progress`，统一读写、统一键名、统一导出。
- **C2 · W3 落盘完成状态**：离线与真实调用分别落盘；真实成功时额外落一份**匿名调用摘要**（服务商/模型/用量/耗时/时间戳，**不含密钥与消息正文**）。
- **C3 · 聚合进度条**：每课顶部粘性显示 `W1✓ W2✓ W3⬜ W4⬜` + 首页总览。W4 的「网页端起步章完成」改为校验四键齐全，而非仅本页勾选。
- **C4 · 首页目录补 W2/W4**：`CourseShell` 对齐规格表四课。

### P3 · 贯通两段旅程

- **D1 · on-ramp 进度导出/导入**：`course-start-progress` 提供导出/导入，与进阶线 `EvidenceLoop` 的机制并列，解决换设备即丢的问题。
- **D2 · 统一「我的进度」视图**：首页一处同时呈现「网页端起步章进度」与「进阶线 checker 证据」，`ProgressWizard` 第 0 步补「先做完 W1–W4 再来跑命令」的衔接。

### 明确不做（防 scope creep，写给后来的实现者）

- 不做排行榜 / 打卡 / 连续天数——违反产品契约的「无排行榜」与隐私边界。
- 不做文本启发式判分——对初学者误判比不判更糟。
- 不做案例库交互筛选——案例库是附录、面向入门后，不占用初学者预算（上一版 C3 砍掉）。
- 不新增术语、不把进阶线内容前移、不引入账号系统或云同步（违反 ADR-0008）。

## 七、建议实施顺序与验收标准

按「先修招牌、再补反馈、后补闭环、最后贯通」，每步一个可独立验收的纵向切片：

1. **Ticket 1（P0）**：A1 + A2（A3 视拍板结果）。
   验收：无密钥学员完成 W3 后，能复述「一次真实调用线上发生了什么」；离线模式展示的是真实样例而非玩笑串。
2. **Ticket 2（P1）**：B1–B4。
   验收：四课交互都能给出「不止自评」的反馈；每课动手前都有预测题；W2 的完成需要引用式自证；错误提示无行话。
3. **Ticket 3（P2）**：C1–C4。
   验收：做完 W1–W4 后，聚合进度条四键全绿；W4 完成提示与四键状态一致；W3 真实调用产生匿名调用摘要；首页四课齐全。
4. **Ticket 4（P3）**：D1 + D2。
   验收：换浏览器可恢复 W1–W4 进度；首页一处看到起步章与进阶线两段进度。

每条 ticket 按 AGENTS.md Definition of Done 收口：更新页面/组件 → 跑 `site` 构建 → 按 WCAG 2.2 AA 查键盘、焦点、对比度、减少动态效果、非颜色编码、文本替代 → 记录验证证据。on-ramp 是纯浏览器路径，但每课仍应在桌面浏览器 + 至少一台移动浏览器实走一遍（BYO-key 的 fetch/CORS 尤其要真机验证，不能只靠构建成功替代）。

## 八、未决事项（需维护者拍板）

1. **W3 真实调用是否允许落盘匿名调用摘要？** 规格承诺「live call record」，本计划默认**落盘**（不含密钥与正文）。若坚持「真实调用零落盘」，则 C2 只写完成标记、不写摘要——但这会继续违反规格自身的承诺，需要明确记录为规格调整。
2. **A3 是否纳入？** 把「创建 API 账户」的引导写进 W3 正文，涉及指向第三方账户页，是否超出课程边界由维护者定。
3. **on-ramp 是否要扩到 5–6 课？** 对真正零基础的人，四课是否足以建立持久心智模型；W2 的「四要素指令」对零基础是否过重，是前提级问题，建议单独评一次再决定，本计划不擅自扩scope。
4. **本计划是「改进提案」，不是已批准规格**。批准后的条目应按仓库惯例升格为 ADR 或 `docs/specs/` 规格，再拆 `ready-for-agent` ticket；不得在实现中顺手扩展范围。

## 九、一句话自评

上一版计划「技术上对、方向上偏」——它会把团队引向一个 localStorage 完美闭环、但初学者仍学不到东西的教程。这一版把北极星换成了「不看答案能不能理解 + 动手 + 得到反馈 + 知道下一步」，招牌主线、反馈深度、完成诚实性依次排到了前面，完成记录降为脚手架。这才是一个面向初学者的可交互教程该修的缺口。
