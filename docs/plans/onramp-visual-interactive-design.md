# 网页端起步章 · 可视化交互升级计划（插画式教学层）

- 状态：设计提案，待维护者批准方向后再拆 ticket
- 日期：2026-08-17
- 上游文档：`docs/plans/onramp-interactivity-assessment.md`（修订版）、`docs/design/t03-brand-spec.md`、`docs/design/t03-common-design-spec.md`、ADR-0003/0005（第三方资产）、ADR-0008（BYO-key）
- 汇总承接：本方案与评估计划已合并为 [v3 起步章交互深化总规格](../specs/agent-engineering-course-v3.md)（草案，待维护者拍板）
- 一句话定位：给 W1–W4 加一个**插画式教学层**——角色化的吉祥物、看得见的概念动画、点击推进的小剧场；**不是整站 rebrand，不是游戏化**。

## 一、先翻译需求：为什么不能字面照做「卡通动漫」

「面向初学者、太简陋、想要卡通动漫」背后的真实需求是对的：零基础学员需要**友好、有隐喻、有情绪安全感**的学习界面。但字面照做「卡通动漫风格」有三个真实风险，必须先摆出来：

1. **与已接受的设计规范冲突**。`t03-brand-spec.md` 明确禁止：emoji 图标、生成插画替代真实产品界面、CSS 剪影/假终端/假 dashboard 冒充产品 UI、紫色渐变万能公式、圆角卡片加左彩色边框。「卡通」如果做成了大眼睛贴纸 + emoji 撒满屏，直接撞墙。
2. **品牌断裂**。全站现有视觉是「Editorial Manual」出版节奏风（衬线大标题、纸白墨绿、证据控制台）。起步章若突兀地变成另一个次元，学员从 W4 走进模块 0 时会经历「画风突变」的身份怀疑。
3. **授权雷区**。「动漫风格」素材通常意味着：第三方 IP 角色（侵权）、素材站下载（许可混杂，违反 ADR-0003/0005 来源账本要求）、AI 生成图（许可归属不清，且品牌规范明确不引入）。三条路都不能走。

**因此本计划把需求翻译为**：**仓内原创的 SVG 角色系统 + 概念可视化动画 + 逐步点击的小剧场交互**，只在 W1–W4 生效，全部资产原创、许可证干净、符合既有禁区。

> ⚠️ **解释边界，需维护者确认**：t03 规范写「不用手绘 SVG、生成插画……**替代真实产品界面**」——其禁令的宾语是「替代产品 UI」。本计划主张：插画用于**解释概念**（Agent 循环、请求旅程），从不用于模拟 Codex/Claude Code/API 的界面。这是对已接受规范的**解释性收窄**，按 AGENTS.md 的真源顺序，需维护者明确批准这一解释，必要时以 ADR 记录。

## 二、双轨视觉策略：「风格随能力成长」

利用 v2 已有的双受众结构，把「画风差异」变成叙事资产而不是缺陷：

| 轨道 | 视觉语言 | 情绪目标 |
| --- | --- | --- |
| 网页端起步章（W1–W4） | 插画式教学层：吉祥物引导、概念动画、柔和圆角 | 「别怕，我带你走」 |
| 进阶线（模块 0–12） | 维持 Editorial Manual 证据风不变 | 「你是工程师了，拿证据说话」 |

衔接点在 W4：小剧场里主角把「工具箱」递给学员、脱下新手帽——页面视觉从插画渐变回编辑风，与 W4「从网页到终端」的心智转折同步。**风格成熟 = 能力成熟**，这让卡通不再是装饰，而成为课程叙事本身。

## 三、角色系统（最小可用集）

只做一个主角 + 三个拟物配角，避免角色泛滥：

1. **主角「小循」（名字待拍板）**：一个圆头圆脑的小机器人实习生。设计硬约束：
   - 无性别、无年龄指向、中性青绿主色（沿用现有 `#087f68` accent，保证与站点同源）；
   - 纯仓内手写 SVG，分层结构（头/身/表情/道具可单独替换），一处定义、四课复用；
   - 表情只用 5 种基础状态（平静、疑惑、恍然、努力、完成），reduced-motion 下有对应静态姿态。
   - **叙事红线**：小循只做**向导**，不做**事实来源**——它可以说「我们来看看下一步」，不能说「OpenAI 的价格是 X」。所有事实仍由正文（证据先行语气）承载，避免吉祥物稀释课程的可信度契约。
2. **拟物配角**（无生命、纯示意）：
   - **钥匙**：W3 的 API key——带计费的钥匙，每次开门掉一枚硬币进计费表；
   - **包裹**：请求/响应的载体——贴着 token 数与耗时标签的小邮包；
   - **环跑道**：W1 的 Agent loop 本体——「模型 → 调用工具 → 观察 → 决定继续/停止」画成一条闭环轨道。

**明确不做**：不给 Codex/Claude Code 画拟人化身（第三方产品人格化有背书暗示风险）；不画任何假的产品界面、假终端、假 dashboard。

## 四、逐课可视化方案

每课一个核心可视化，且都与既有修订版计划（P0/P1）**咬合而非重叠**——动画承载教学，证据仍走真实数据。

### W1 · Agent 循环跑道（对应修订版 B3「重做」）
小循站在环形跑道上，跑道四个站点：收到输入 → 生成输出 → 调用工具 → 观察结果并决定。**学员点击才推进到下一站**（非自动播放），每停一站弹出该步的普通话解释。跑到「停止条件」站时小循举旗。配 2 道预测题：跑之前先猜「模型自己会停吗？」。这同时就是 StartQuiz 升级的载体——答错回跑道对应站点重看。

### W2 · 指令小剧场 + 拖拽配对（对应修订版 B2「引用式自证」）
左右分镜动画：小循收到**模糊指令**（「帮我把周报弄清楚些」）时头顶问号、在原地打转、递出三份互相矛盾的结果；收到**结构化指令**后头顶亮灯、按目标/上下文/约束/验收标准四格抽屉依次取料。学员先把四要素卡片**拖拽**到模糊指令的改写位，再进入自己的文字改写。拖拽是「操作前预测」的身体化版本；最终自证仍用修订版 B2 的引用式勾选，不用文本判分。

### W3 · 请求之旅（对应修订版 A1「真实样例」，二者是同一个组件的两层）
这是旗舰可视化：一个贴着标签的**包裹**从浏览器出发，穿过 HTTPS 隧道，抵达服务商大楼（门口有「验钥匙 + 计费」关卡），带着回复包裹返回。**包裹上的标签数字来自真实记录的样例数据**（真实 token 数、真实耗时、真实端点）——动画是壳，证据是芯。离线模式下演示的就是这份已标注的真实样例；真实调用模式下，动画回放**学员刚才那次调用**的真实数字。钥匙丢失/失效时播放「钥匙被关卡退回」的错误分支动画，配普通话解释（对应修订版 B4 去行话）。

### W4 · 分岔地图（对应修订版 C3「聚合进度」）
一张插画风地图：左边「浏览器之路」（已完成 W1–W3 的脚印），右边「终端之门」（模块 0 起）。小循把工具箱递给学员。地图上直接嵌入 W1–W4 聚合进度脚印（读共享进度模块），四枚脚印齐了门才发光——**进度闭环也顺势有了视觉形态**。

## 五、交互形态的边界

**做**：
- 点击推进（学生控制节奏，天然承载「预测→验证」）；
- 拖拽配对（W2 四要素）；
- 动画回放真实数据（W3）；
- 每个动画的静态等价物（noscript / reduced-motion / 打印）。

**不做**（产品契约与设计禁区双重约束）：
- 积分、徽章、连续打卡、排行榜——AGENTS.md 明令无排行榜，游戏化成瘾机制与「可核验成果」哲学相悖；
- 自动播放长动画、音效（默认静音站点的惯例，且无障碍负担大）；
- emoji 图标、紫色渐变、圆角卡片左彩边（t03 禁区）；
- 用插画模拟任何真实产品 UI（Codex/Claude Code/服务商控制台）。

## 六、技术选型（三案对比，推荐 A）

| 方案 | 说明 | 优点 | 否决/风险 |
| --- | --- | --- | --- |
| **A（推荐）仓内原创 SVG + CSS/JS 动画** | 小循与配角全部为 Astro 组件内嵌 SVG，用 CSS transition/`@keyframes` + 少量 JS 状态机驱动；点击推进 = 状态机步进 | 零新依赖（符合静态优先）；许可证 100% 干净；reduced-motion 可精确控制为静态帧；与现有组件工作流（StartQuiz 等）同构 | 表现力上限低于专业动画；需要一次性绘制工时 |
| B · Lottie（lottie-web + JSON 动画） | 表现力强、设计师友好 | 动画质量高 | 新增运行时依赖；JSON 资产产自 AE 等闭源工具链；资产授权需逐个入账本；无 JS 时完全不可用。**暂不采用，留作未来升级路径** |
| C · Canvas/游戏引擎（Phaser 等） | 游戏级表现 | 上限最高 | 依赖重、无障碍几乎不可做、与静态站哲学冲突。**否决** |

技术落地要点（方案 A）：
- 角色 SVG 集中放在 `site/src/components/mascot/`（`Mascot.astro` 接收 `pose`/`mood` props），四课复用；
- 动画状态机用现有模式：`data-*` 属性 + 事件监听，与 `StartQuiz`/`ByoKeyChat` 的实现风格一致，不引入框架 island 也能做（如需复杂状态再用 React island，AGENTS.md 已允许「少量 React islands」）；
- 每个动画组件提供 `prefers-reduced-motion` 分支：改为分步静态帧 + 「下一帧」按钮；
- 所有动效同时有 `aria-live` 文字播报（「包裹已到达服务商，正在验证钥匙」）。

## 七、设计规范增补（插画层专用）

在 t03 规范基础上，为插画层增补四条（批准后并入设计文档）：

1. **色板同源**：插画主色沿用站点 accent `#087f68` 及纸白底；允许最多 3 个插画辅助色（如暖黄「恍然」、赤陶橙警示，后者与 Claude Code mark 的赤陶橙区分为不同色值并仅用于状态提示）；
2. **排印不变**：正文仍 Noto Sans SC 16px+/1.7 行高，插画内文字最小 14px 且仅限标注；
3. **形态语言**：圆润但克制——圆角用于角色与舞台，**不**用于内容卡片（避免撞上「圆角卡片加左彩边」禁区的观感）；线条粗细统一（建议 2.5px 描边基准）；
4. **面积预算**：单课插画元素不超过首屏面积的 40%，教学文字永远是主角。

## 八、授权与来源账本

- 小循与全部配角、场景：**仓内原创 SVG**，随内容以 CC BY 4.0 发布，记入来源账本（作者：本仓库贡献者）；
- 明确不引入：AI 生成插画（许可归属不清 + 规范禁止）、动漫素材站资产（许可混杂）、任何第三方 IP 角色的化用或致敬改名；
- 不复刻任何官方产品的吉祥物/插画风格（不暗示背书）。

## 九、实施顺序（ticket 草案）

依赖关系标注：〔P0〕〔P1〕〔P2〕指修订版评估计划中的对应项。

| # | 交付物 | 内容 | 依赖 | 验收标准 |
| --- | --- | --- | --- | --- |
| V1-0 | 插画设计语言 spec + 小循定稿 | 一页插画层规范（第七节内容成文）+ 小循 5 姿态 SVG + 配角三件套定稿 | 无 | 维护者签认角色与规范；SVG 通过对比度与缩放检查 |
| V1-1 | W1 循环跑道 | 点击推进的 Agent loop 动画 + 2 道预测题 + 错题回站点 | V1-0；〔P1-B3〕 | 学员不看答案能复述循环四步；reduced-motion 下为静态分帧 |
| V1-2 | W3 请求之旅 | 包裹旅程动画，离线挂载真实样例数据，真实模式回放学员实调数字；错误分支动画 + 普通话提示 | V1-0；**〔P0-A1〕必须先行或同票** | 离线模式展示的是真实记录样例而非预制串；错误提示无行话 |
| V1-3 | W2 指令小剧场 | 模糊/结构化双分镜 + 四要素拖拽 + 引用式自证 | V1-0；〔P1-B2〕 | 拖拽可用键盘替代操作；完成需引用式自证 |
| V1-4 | W4 分岔地图 + 画风衔接 | 插画地图嵌聚合进度脚印；插画→编辑风的过渡段 | V1-0；〔P2-C1/C3〕（共享进度模块先行） | 四枚脚印齐才亮门；W4→模块 0 的视觉过渡不突兀 |

每票按 AGENTS.md Definition of Done 收口：构建通过、WCAG 2.2 AA（键盘、焦点、对比度、reduced-motion、非颜色编码、文本替代）、桌面 + 移动浏览器实走、验证证据入 worklog。

**与修订版计划的总排序建议**：P0（A1/A2 证据主线）先于或伴随 V1-2 进行——**证据先行，插画包壳**；不要反过来先做漂亮的动画、再补真实数据，那是本仓库哲学的倒置。

## 十、风险清单与未决事项

1. **规范解释权**（第一节 ⚠️）：插画「解释概念、不模拟产品 UI」的边界解释需维护者批准，建议以轻量 ADR 记录，避免未来贡献者误判。
2. **绘制工时**：方案 A 的成本主要是小循 5 姿态 + 三配角 + 四场景的 SVG 绘制。若维护者/贡献者无手绘带宽，备选是「几何极简风」（纯几何形状拼角色，无手绘感但同样友好），表现力略低但可完全由代码生成。**需拍板选哪条**。
3. **角色命名**：「小循」（loop 谐音）是本计划占位名，需维护者定名（或另征集）。
4. **维护成本**：插画层让 W1–W4 组件复杂度上升约一倍，后续每次改动需同时维护动画逻辑与静态等价物。若觉得重，可缩为「V1-0 + V1-2（只做旗舰）」的最小版。
5. **不做整站 rebrand**：进阶线 26 课维持现状，本计划不触碰。

## 十一、一句话总结

不是把课程变成动漫，而是给零基础学员请一位**仓内原创、许可证干净、只引导不背书的小向导**，配四段**点击推进、数据真实**的概念动画——风格随能力成长，在 W4 把画风和钥匙一起交还给学员。
