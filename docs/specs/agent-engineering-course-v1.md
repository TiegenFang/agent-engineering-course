# 《Agent 工程入门》v1 网页课程规格

## Problem Statement

希望系统学习 Agent 的科研人员和企业技术人员，当前面对的是一组彼此割裂且快速变化的资料：有些内容只介绍模型或提示词，有些只罗列某个 Coding Agent 的功能，有些把 Memory、上下文、Skill、Plugin、MCP 与 API 混为一谈，还有不少教程默认学员熟悉 POSIX Shell、Git 和特定云平台。学员即使照着示例成功运行，也往往不能解释 Agent 为什么成功、失败发生在哪里、如何迁移到另一工具，或如何证明结果可信。

用户需要一门公开、中文、可版本化的网页课程，让科研与企业团队中的技术型 Agent 初学者从最小环境和 Git 习惯开始，逐步理解厂商无关的 Agent 能力模型，并在真实代码仓库中平等使用 Codex 与 Claude Code。课程还必须深入覆盖 Agent 指令工程、上下文管理、Memory、Skill、Plugin、MCP 与 API，提供真实故障、恢复路径和可核验成果，同时对版本、成本、权限、安全、来源和许可证保持透明。

这门课程不能只是阅读材料集合。它需要把静态课程站、公共练习仓库、本地课程检查器、匿名学习记录、来源账本和发布门槛组合为一个可持续维护的课程产品，并证明学员能够走通完整学习旅程。

## Solution

构建公开课程“Agent 工程入门：从 Codex 与 Claude Code，到 Memory、Skills、MCP 与 API 实战”。课程采用厂商无关的稳定知识层和易变的工具适配层，以 13 个模块覆盖前置环境、Agent 与 Harness、Agent 指令工程、双 Coding Agent、安全规则、上下文、Memory、Skill、Plugin、MCP、编排、最小 API Agent loop 以及生产化结课。

核心课程为 20–24 小时，要求学员使用至少一种 Coding Agent 在真实仓库中完成任务，并掌握上下文、Memory、Skill 与 MCP；进阶实战额外需要 8–12 小时，要求学员使用 Python 和官方 API/SDK 手写最小 Agent loop。Codex 与 Claude Code 交替承担主实验，另一工具通过迁移挑战验证跨工具能力。科研与企业学员共享一套能力主线，再分别完成可复现科研工作流或 Issue-to-PR 工程工作流结课项目。

课程使用合成的“设备遥测与报告工具”作为贯穿式公共练习仓库。所有正式课节产出可核验成果，由本地 Python 课程检查器检查并生成匿名 JSON；网页只在浏览器本地保存学习记录。网站使用静态、内容优先架构，并以同一课程版本锁定网页、练习、检查规则和工具适配信息。

## User Stories

1. 作为一名技术型 Agent 初学者，我希望先看到课程适合谁和不适合谁，以便判断投入时间是否值得。
2. 作为一名没有稳定 Git 习惯的学员，我希望获得简短的前置技能补给站，以便不因隐含前提而在第一章受阻。
3. 作为一名 Windows 学员，我希望所有正式命令都以 Windows 11 与 PowerShell 7 为主路径，以便在自己的真实环境中复现结果。
4. 作为一名 macOS 或 Linux 学员，我希望看到明确标注的平台差异，以便把主路径安全迁移到本机。
5. 作为一名 Git 初学者，我希望练习建立修改前基线，以便随时辨认 Agent 改了什么。
6. 作为一名 Git 初学者，我希望练习查看状态和差异后再提交，以便避免盲目接受 Agent 输出。
7. 作为一名担心误操作的学员，我希望练习恢复工作区，以便知道错误并不一定意味着重来。
8. 作为一名处理科研或企业代码的学员，我希望学习忽略密钥和敏感文件，以便降低泄漏风险。
9. 作为一名初学者，我希望区分模型、Agent、Agent Harness、Coding Agent 与 Agent Application，以便建立正确的心智模型。
10. 作为一名初学者，我希望可视化观察最小 Agent loop，以便理解响应、工具调用、结果回填和停止条件。
11. 作为一名学习者，我希望在操作前预测 Agent 的下一步，以便从被动观看转为主动推理。
12. 作为一名经常给出模糊需求的用户，我希望比较模糊请求与工程化指令，以便看到质量差异来自哪里。
13. 作为一名 Agent 使用者，我希望学习表达目标、上下文、约束和非目标，以便减少无关工作。
14. 作为一名 Agent 使用者，我希望学习规定输出契约与验收标准，以便让任务结束条件可验证。
15. 作为一名工具设计者，我希望学习编写清楚的工具描述，以便模型正确选择和调用工具。

17. 作为一名 Codex 新用户，我希望完成一次安全的仓库任务，以便掌握澄清、计划、执行、验证和交付的完整节奏。

19. 作为一名只能访问 Codex 的学员，我希望仍能完成核心课程，以便不被双订阅要求排除。

## Implementation Decisions

- 课程产品定位为公开、免费、可版本化自学的中文网页课程，主要面向科研与企业团队中的技术型 Agent 初学者。
- Coding Agent 工程约占主线的三分之二，Agent Application 工程约占三分之一；后者负责解释底层能力并形成进阶路径。
- 核心课程目标时长为 20–24 小时，进阶实战额外为 8–12 小时。核心结业要求真实仓库任务、上下文管理、Memory、Skill 与 MCP；进阶结业增加最小 API Agent。
- 课程设置 13 个模块：前置技能补给站；Agent、模型与 Harness；Agent 指令工程；Codex 与 Claude Code 安全起步；项目指令与规则作用域；上下文工程；Memory；Skill；Plugin；MCP；Hooks、Tasks、Subagents 与多 Agent；Python 最小 API Agent loop；生产化与双轨结课。
- 使用厂商无关的 Agent 能力模型作为稳定知识层。Codex、Claude Code、模型、SDK、API、安装和配置属于工具适配层，必须携带适用版本、核验日期和变更记录。
- Codex 与 Claude Code 保持同等重要并交替主讲。每个能力单元只制作一个完整主实验，另一工具通过差异说明和变化输入的迁移挑战出现，不制作两套逐步骤重复课程。
- 学员至少拥有一种 Coding Agent 即可完成核心线；完整双工具对照和 API 进阶按账号与成本提供分层访问说明。
- Windows 11 与 PowerShell 7 是所有正式本地实验的主路径。macOS 和 Linux 提供显式差异说明和至少一条跨平台复核路径。首版不提供云端浏览器 IDE。
- 前置 Git 内容限制在课程必需的安全工作流：建立基线、查看状态和差异、暂存、提交、分支、历史、忽略敏感文件、恢复，以及冲突和 worktree 风险意识。
- Agent 指令工程覆盖目标、上下文、约束、非目标、示例、输出契约、结构化输出、工具描述、验收标准、失败证据、冲突、提示注入和过长指令，不建设脱离场景的万能 Prompt 库。
- 公共练习仓库使用合成“设备遥测与报告工具”，包含问题数据、Python 分析与绘图、报告生成、CLI、测试、文档、预置任务、故障和上下文噪声。科研与企业轨道对同一项目采用不同交付视角。
- 科研结课轨道交付可复现数据检查、分析、图表、实验记录和报告；企业结课轨道交付 Issue 澄清、计划、实现、测试、评审和交付说明。两者共享问题定义、上下文质量、操作安全、验证证据、可复现性、迁移能力和交付清晰度评价维度。
- 每个实操课节采用固定课节语法：真实问题、心智模型、操作前预测、主工具演示、本地实验、故障注入与恢复、迁移挑战、可核验成果、风险与来源说明。
- 每个正式实操课节必须提供内容契约，覆盖课节身份、阶段、时长、先修、学习成果、产物、主讲与迁移工具、平台、客户端、SDK、模型、协议、核验日期、账号、成本、权限、副作用、来源、许可证和过时风险。
- 所有课节嵌入风险与验证卡片，明确成功证据、预期失败、恢复方法、权限、外部副作用、成本、隐私、人工确认点和版本边界。
- 渐进式解题支持固定为预测、方向提示、诊断提示、本地检查证据和带解释参考实现。迁移挑战使用变化输入，不采用防作弊机制。
- 课程检查器提供统一的课节标识入口，在学员本机检查产物和证据，同时输出人类可读结果与匿名 JSON。检查器不得上传源码、密钥或运行数据，也不得要求唯一实现。
- 匿名 JSON 是检查器与网页之间的公开交换契约。网页只在用户主动导入时读取结果，并把状态保存到浏览器本地。
- 首版不设置账号、服务端数据库、分析脚本、广告或跨用户排行榜。学习记录支持本地 JSON 导出与导入。
- 静态课程站采用 Astro、Starlight 与 MDX，只有能力地图、Agent loop、指令对照、上下文预算、知识检查和本地进度等交互使用少量 React islands。
- 课程工作区作为单一公开仓库管理静态网站、公共练习、Python 检查器、规划与来源文档。网页、练习、检查规则和版本元数据由同一 release tag 锁定。
- 首个 Alpha 必须是贯通产品的纵向切片，而不是只有首页：包含首页、能力地图、模块 0–3、Agent loop 交互、指令对照、双工具任务、上下文预算模拟器、公共练习基线和首个检查器。
- 在正式视觉实现前，使用同一真实内容制作三种可交互设计方向供评审；视觉结果必须避免通用模板感，并服从课程可读性、代码学习和无障碍要求。
- 移动端支持完整阅读、搜索、知识检查、模拟器和进度管理；终端、Git、Coding Agent、Python 与 MCP 实验明确要求桌面环境。
- 无障碍最低目标为 WCAG 2.2 AA，包括键盘、焦点、对比度、减少动态效果、非颜色编码、图示文本说明和媒体字幕。
- API 进阶主语言为 Python，TypeScript 只提供对照附录。学员先使用官方 API/SDK 手写最小 Agent loop，再在选修内容比较上层框架。
- 最小 Agent loop 必须显式呈现模型响应、工具请求、工具执行、结果回填、状态所有权、停止条件、错误恢复和预算限制。
- MCP 实验必须使用真实协议 transport 和官方检查工具形成调用证据。进程内替身可以解释概念，但不能作为正式 MCP 实验的完成证据。
- 上下文与 Memory 是全课最深入的主题；Skill 与 MCP 要求完整动手；Plugin 重点教授系统视角、打包和供应链；多 Agent 只安排一次受控对照实验。
- 来源治理严格区分事实真源与重点参考集。当前产品行为、协议和配置以 OpenAI、Anthropic、MCP 与 Agent Skills 官方资料为准；热门仓库只用于课程梯度、机制实验和模式参考。
- 重点参考集固定包含 `shareAI-lab/learn-claude-code`、`microsoft/ai-agents-for-beginners`、`anthropics/skills`、`microsoft/mcp-for-beginners`、`wshobson/agents`、`openai/codex` 和 `anthropics/claude-code`。
- `shareAI-lab/learn-claude-code` 的采用基线固定到已审计 commit。课程重写其增量机制思路，不直接沿用弱命令黑名单、`shell=True`、POSIX 假设或不含真实 transport 的 MCP 示例。
- 原创正文和图解采用 CC BY 4.0，自有代码、练习脚手架和检查器采用 MIT，第三方资产保留各自许可证并进入来源账本。
- 网站通过 GitHub Actions 部署至 GitHub Pages，自定义域名延后。GitHub Issues 承担错误、过时、无障碍和安全报告，Discussions 承担问答与展示，Pull Requests 承担勘误和适配改进。
- 首版不承诺实时聊天社区。安装或复杂交互可以补充短视频，但全部必要信息必须保留可搜索文字与字幕。
- 维护节奏为每周自动检查链接、依赖和上游发行，每月人工复核工具适配层，每季度形成课程版本，关键安全、安装、API 与 MCP 变化紧急修订。自动化不得盲目改写教材。
- 实施分为 Foundation、Alpha 纵向切片、Core Beta 和 v1 四个里程碑。发布日期在 Alpha 获得真实制作速度后确定。
- 编辑语气采用证据先行的资深工程师指导风格，避免营销夸张，明确工具差异，并解释失败、恢复和证据强度。

## Testing Decisions

- 好测试只验证学员和维护者可观察的行为、产物与证据，不断言页面组件、内部函数、目录实现或特定答案形状。
- 唯一的最高层测试接缝是端到端学习旅程：从一个锁定课程版本出发，学员能够在 Windows 11 + PowerShell 7 环境打开课程、完成正式实验、通过课程检查器获得匿名 JSON，并将结果导入网页形成可核验完成状态。
- 内容契约校验、链接与许可证扫描、检查器样例测试、模拟器单元测试和浏览器检查都是最高层旅程的下层验证器，不建立互相竞争的产品验收接缝。
- 纵向切片必须先实现并自动化一条完整学习旅程，以验证静态网站、公共练习、检查器和本地进度之间的契约，再批量扩展课程内容。
- 静态站测试验证公开路由可访问、导航和搜索能找到内容、代码与命令可读、交互在禁用 JavaScript 或加载失败时具有合理降级。
- 内容契约测试验证所有正式实操课节具备必填元数据、有效先修关系、可解析来源、核验日期和明确的风险信息。
- 公共练习测试使用已知正确基线、代表性故障和变化输入，验证任务可以被完成和恢复，而不是只适配作者路径。
- 课程检查器测试同时覆盖已知正确成果、部分完成、错误成果、替代实现、缺失依赖和敏感文件场景，确保结果判断稳定且不泄露数据。
- 匿名 JSON 契约测试验证版本、课节身份、结果与证据摘要可以导入和导出，未知字段可安全忽略，不包含源码、密钥、绝对个人路径或原始研究数据。
- 本地进度测试验证无账号使用、刷新后保留、JSON 导出、JSON 导入、版本不兼容提示和用户主动清除。
- Agent loop、上下文预算和指令对照等交互组件分别测试键盘操作、减少动态效果、变化输入、边界值和可解释输出。
- 所有正式本地实验必须在 Windows 11 + PowerShell 7 实际运行。每个课程版本还要在 macOS 或 Linux 至少复核一条对应路径，并记录平台差异。
- Codex 与 Claude Code 的工具适配实验分别进行现场复核；只拥有一种工具的核心路径和双工具迁移路径都必须可完成。
- API 实验使用确定性夹具验证控制流，并在发布前执行受预算限制的 OpenAI 与 Anthropic 现场冒烟测试。现场结果记录模型、SDK、日期、成本和已知不确定性。
- MCP 正式实验通过真实 transport 和官方检查工具验证能力发现、调用、失败恢复与权限提示；纯进程内模拟不能满足该测试。
- 安全测试检查明文密钥、危险默认权限、无边界命令、未说明副作用、提示注入、敏感数据上传和不可恢复步骤。
- 无障碍测试包含自动扫描和人工键盘、焦点、阅读顺序、对比度、减少动态效果、非颜色编码与字幕复核。目标基线为 WCAG 2.2 AA。
- 来源与许可测试验证每项第三方资产存在来源、固定版本、用途和许可证记录，并阻止不明资产进入发布包。
- 版本测试验证网页内容、练习基线、检查规则和工具适配信息属于同一课程版本，并在不兼容时向学员给出明确提示。
- Alpha 由 8–12 名代表性初学者试学，覆盖科研/企业背景、有/无 Git 习惯、Codex-only、Claude-only 和双工具条件。审计记录阻塞点、观察和可核验结果，不只记录满意度。
- Alpha 成功指标为至少 80% 完成环境基线、至少 70% 产出首个可核验成果、至少 60% 完成迁移挑战，并且没有关键安全、密钥、失效命令或不可恢复问题。
- 当前仓库没有可复用的既有应用测试套件。测试先例来自已确认的课程检查器契约、课节语法、发布门槛和纵向切片设计；实现时优先建立一个端到端验收入口，再补充必要的下层验证器。

## Out of Scope

- 模型训练、微调和强化学习。
- 完整 RAG 或向量数据库平台课程。
- Agents SDK、Claude Agent SDK 或其他多 Agent 框架的系统课程；它们只作为最小循环之后的选修比较。
- 无代码 Agent 平台。
- 复杂云部署、Kubernetes、SSO 和企业身份治理。
- Codex 或 Claude Code 全部 CLI 参数的参考手册。
- Cursor、Copilot、Gemini 等其他 Coding Agent 的完整并行课程。
- 首版云端浏览器 IDE、云端判题、账号系统、数据库、跨设备同步、排行榜、分析脚本和广告。
- 实时 Discord、微信群或同类社区支持承诺。
- 认证考试题库、防作弊监控和学习者排名。
- 使用真实敏感科研数据或企业数据作为公共练习材料。
- 在 Alpha 获得实际制作速度前承诺具体发布日期。
