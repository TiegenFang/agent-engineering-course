# T03 共同设计 Spec：可见方向评审

> 状态：reviewable design demo；等待维护者视觉选择，不是最终生产主题。
> 固化日期：2026-08-13
> 适用范围：Issue #4 / Foundation → Alpha 的可见方向评审

## 项目、受众与使用场景

“Agent 工程入门”是一门公开、免费、可版本化的中文网页课程，面向科研与企业团队中的技术型 Agent 初学者。受众能使用编辑器、终端和 Git，能阅读少量 Python 或 JavaScript，但尚未形成关于 Agent、上下文、Memory、Skill、Plugin、MCP 和 API 的稳定心智模型。首页第一次见面的任务不是推销一个模型，而是让学员在十几秒内判断“这门课是否适合我、我会留下什么证据、哪些实验需要桌面环境”。维护者的任务是比较三种真正可打开的视觉方向，而不是从抽象风格名中盲选。

页面会服务三个相互连接的场景：桌面宽屏上快速扫读课程边界、能力地图和模块顺序；移动端在碎片时间完整阅读，不把移动端伪装成终端实验；桌面实战前回到站点确认 Windows 11 + PowerShell 7、Codex、Claude Code、Python 与 MCP 的权限、成本和验证边界。三版都必须把“可核验成果”放在视觉层级中，而不是把页面做成只看 hero 的营销落地页。实验真正发生在本地仓库，网站只提供内容、交互和本地学习记录入口。

## 同一份真实内容

三版共用 `site/src/data/t03-content.ts` 中的事实内容，不能改写成 Lorem、假 stats、虚构 testimonials 或装饰性 KPI。共同内容包括课程名称与副标题、由根目录 `course-version.json` 提供的课程版本、核心线 20–24 小时、进阶线 8–12 小时、课程定位、八层 Agent 能力模型、模块 0–3 的真实问题与产物、四个课程工作区边界、四条可核验成果原则，以及 Codex 与 Claude Code 交替主讲和迁移挑战的关系。页面还必须呈现“风险与验证卡片”这个课程领域术语，提示账号、成本、权限、副作用、版本和来源不是页脚装饰，而是每个实战单元的证据接口。

能力地图的八层顺序固定为：模型与 API、指令与规则、上下文与状态、Memory、工具与 MCP、Skill 与 Plugin、编排与多 Agent、评测/安全/成本与运维。课节内容固定为模块 0 前置技能补给站、模块 1 Agent/模型/Harness、模块 2 Agent 指令工程、模块 3 Codex 与 Claude Code 安全起步。三版可以选择列表、轴线、网格或控制台来表达，但不能隐藏或替换这些内容，也不能暗示尚未实现的后续模块已完成。

## 输出尺寸、情绪与信息密度

每版是 Astro/Starlight 仓库中的可运行 review route，桌面基准为 1440×900，移动基准约 390px 宽（以 390×844 作为浏览器检查视口）。页面不是固定海报：桌面允许纵向滚动，移动端正文、能力地图、模块和风险说明都必须可读。正文中文最小 16px，行高约 1.7–1.8，正文行长控制在约 28–36 个汉字；交互 hit target 不小于 44×44px。三版都需要清晰的标题层级、短段落和可回到主要内容的跳过链接。

三种方向使用同一内容、但刻意拉开信息架构、布局、排印、节奏和交互：一版稳妥可读，以功能主义网格和公开文档式导航为底盘；一版迁移现实标杆，把官方产品文档和出版物的阅读节奏迁移到课程首页；一版大胆定制，把能力模型变成现场证据控制台，用高密度但有来源的状态、步骤和关系表达学习路径。颜色不是主要差异维度，不能把三版做成同一个圆角卡片模板只换色。所有方向禁止全屏紫色渐变、emoji 图标、虚构 stats/testimonials、圆角卡片加左彩色 border、装饰性 icon 泛滥和 CSS/SVG 冒充产品截图。

## 可访问性与交互底线

三版至少达到 WCAG 2.2 AA 的方向评审基线：语义化 landmark、一个明确的 `main`、可见键盘焦点、合理 Tab 顺序、按钮和链接拥有可理解名称、状态不只依赖颜色、正文对比度至少 4.5:1、大字至少 3:1。原生 `<details>`、真实按钮和链接优先于不可达的 div 点击区；交互状态要有 `aria-expanded` 或可读文本。`prefers-reduced-motion: reduce` 下必须关闭或缩短入场、滚动和闪烁动效，不能仅写注释。移动端不把横向滚动作为阅读前提，宽表格改为堆叠或可聚焦的纵向结构。

## 必含元素与图片策略

每版必须包含：课程 hero、版本/时长/工作区合同、八层能力地图、模块 0–3 课节预览、Codex 与 Claude Code 的同等关系、至少一个可操作的能力/课节交互、风险与验证边界、方向说明和回到方向索引的链接。页面中具名呈现的产品只使用通过资产协议核验的官方 mark：Claude Code 使用 Anthropic 官方 press kit 的 Slate SVG；OpenAI/Codex 使用真实文本 mark，并链接 OpenAI 官方 Design/产品页面，官方 wordmark 只作为受品牌条款约束的可选远程资产，不在仓库中重新绘制。Anthropic/Claude Code 的本地 SVG 同样保留其原始比例，不改色、不拉伸、不暗示背书。

官方 UI 截图即使在产品页面可见，也不默认拥有可再发布许可；本次不下载或重制真实界面，不编造终端截图、任务数据或用户数据。需要表达“界面待核准”时使用文字说明和明确的“官方 UI 截图待许可核准”占位，不把灰块伪装成真实产品。装饰图片不是内容必需品，因此本 demo 不使用 stock photo、生成插画或 CSS 产品剪影。若后续课程需要真实 UI，应重新走官方 press kit、产品页面许可与来源账本审计，并把版本和核验日期写入工具适配层。

## 方向选择边界

本 spec 是三套逻辑唯一共同输入。方向一是“Quiet Grid / 可读校准”（稳妥可读）；方向二是“Editorial Manual / 现实迁移”（以当前 Claude Code 官方文档和出版物阅读秩序为参照，但不复制其界面）；方向三是“Evidence Console / 现场证据”（大胆定制，把学习证据和能力关系做成控制台）。维护者可以选择一版继续深化，也可以混合：例如采用 Quiet Grid 的移动阅读和 Editorial Manual 的章节节奏，再取 Evidence Console 的能力地图交互。评审完成前不应把任一方向写成正式品牌主题、生产导航或课程最终首页。
