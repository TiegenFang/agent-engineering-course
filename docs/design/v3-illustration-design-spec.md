# V3 教学插画层设计语言 Spec

> 状态：已接受（V3-2 定稿，2026-08-17）
> 上游决策：[ADR-0009](../adr/0009-teaching-illustration-layer-boundaries.md)（插画层边界）
> 依据：[v3 起步章交互深化总规格](../specs/agent-engineering-course-v3.md) 第 5 节、[可视化交互升级计划](../plans/onramp-visual-interactive-design.md) 第七节
> 实现位置：`site/src/components/mascot/`（`Mascot.astro`、`Cast.astro`、`poses.ts`）
> 预览页：`/mascot-preview/`（不进侧栏导航的内部评审页）

本 spec 在 `t03-common-design-spec.md` 与 `t03-brand-spec.md` 之上为**网页端起步章（W1–W4）插画层**增补设计规则；进阶线（模块 0–12）视觉不变。ADR-0009 的七条边界（只解释概念、不模拟产品 UI、吉祥物不做事实来源、不给第三方产品拟人化身、仓内原创、t03 解释性收窄、作用范围）对本 spec 全部有效，此处不重复、只落实。

## 一、角色系统（几何极简路线）

全部角色由纯几何形状（圆、矩形、圆角矩形、线段、少量二次曲线）拼装，无手绘笔触、无位图、无渐变，可完全由代码生成与审查。

### 主角「小循」

圆头圆脑的小机器人实习生；中性、无性别年龄指向；青绿主色与站点同源。一处定义（`Mascot.astro`），四课按 props 复用：`<Mascot pose="puzzled" size={120} />`。

| 姿态 | pose 值 | 形态要点 | 教学用途 |
| --- | --- | --- | --- |
| 平静 | `calm` | 中性表情、双臂下垂、胸口待机指示灯 | 默认向导与站旁陪伴 |
| 疑惑 | `puzzled` | 头顶暖黄问号、眉梢内挑、嘴部收圆、单手抬起 | 操作前预测、模糊指令演示 |
| 恍然 | `insight` | 天线换灯泡 + 射线、眯眼笑、双臂张开 | 概念揭晓与对照解释 |
| 努力 | `effort` | 挑眉抿嘴、双臂高举带运动短线与汗滴 | 学员动手实验、等待真实调用 |
| 完成 | `done` | 举完成旗、胸口亮对勾徽章 | 可核验成果达成、单元完成 |

姿态是**表情与肢体的组合**，不是位移动画；切换姿态即静态等价物本身。小循的台词气泡（由使用方 HTML 提供）只能包含引导语与情绪语，不得包含产品事实（ADR-0009 第 2 条）。

### 拟物配角三件套（`Cast.astro`）

| 配角 | role 值 | 形态要点 | 教学用途 |
| --- | --- | --- | --- |
| 带计费的钥匙 | `key` | 钥匙 + 计费表盘 + 正在下落的硬币 | W3 API key：证明身份、按用量扣费 |
| 贴 token 标签的包裹 | `package` | 邮包 + 十字捆扎 + token 标签（`label` prop 传入） | W3 请求/响应载体；标签必须传真实记录数字 |
| 环跑道 | `track` | 闭环跑道 + 内侧虚线车道 + 四编号站点 + 方向箭头 | W1 Agent loop：输入→生成→调工具→观察决定 |

配角无生命、无表情、无台词；不拟人化任何第三方产品（ADR-0009 第 3 条）。

### W4 分岔地图场景元素（V3-6 增补）

W4 收尾页（`site/src/components/TerminalBridge.astro`）在角色与三件套之外内嵌一张分岔地图场景，元素全部为几何形状，沿用上表同一色板与 2.5 描边基准：

| 元素 | 形态要点 | 状态与静态等价物 |
| --- | --- | --- |
| 脚印 ×3 | 前掌椭圆 + 脚跟圆，沿「浏览器之路」虚线小路分布 | 该课完成 = accent 填充 + 对勾徽章；未完成 = 留白描边。点亮状态另配 HTML「已点亮/未点亮」文字标签与跳转链接，不单靠颜色编码 |
| 终端之门 | 门框 + 门板 + 门楣四钥匙孔（W1/W2/W3/本页确认各一） | 四键齐 = 门板静态旋开 + 暖黄门缝 + 静态光芒线；未齐 = 门板闭合、钥匙孔按各自状态填充。门的开合状态另配「已打开/未点亮」文字 |
| 工具箱 | 箱体 + 提手 + 搭扣 + 面板刻线的递交接棒道具 | 由 done 姿态小循随身出示，无独立状态；图注文字随完成切换 |

- 门与脚印的状态数据全部来自共享进度模块（`readStartProgress()`）：页面加载、手动「刷新脚印进度」按钮与跨标签页 `storage` 事件三个入口同源刷新。
- **本场景所有状态切换一律为静态替换（class/hidden 切换），不携带任何动画或过渡**——这是 V3-6 的明确决定：W4 的画风衔接（插画层 → Editorial 编辑风）是样式语言切换，与 `prefers-reduced-motion` 无关。
- W4 完成后，完成区域从插画层切回 Editorial 编辑风（默认站点排版、直角分隔线、无插画卡片），即 D3「风格随能力成长」的衔接点。

## 二、色板（与站点同源）

主色沿用站点 accent（`site/src/styles/custom.css`：浅 `--sl-color-accent: #087f68`、深 `#6dd9bd`）。插画层专用 token 定义在组件内 CSS 变量，随 `data-theme` 自动切换，并可被 `scheme="light|dark"` 强制：

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--xun-ink` | `#1c2b26` | `#e9f5ef` | 描边与插画内文字（唯一文字色系） |
| `--xun-accent` | `#087f68` | `#6dd9bd` | 青绿主色（同源站点 accent） |
| `--xun-accent-deep` | `#05604f` | `#9ff0d9` | 完成徽章等强调细节 |
| `--xun-on-accent` | `#ffffff` | `#17181c` | accent 填充上的文字（站点数字、对勾） |
| `--xun-fill` | `#eaf6f1` | `#143a32` | 身体/面板装饰填充 |
| `--xun-paper` | `#ffffff` | `#17181c` | 角色留白底 |
| `--xun-yellow` | `#ffd76a` | `#ffd76a` | 恍然灯泡、旗面、硬币等状态提示填充 |
| `--xun-warn` | `#b0492a` | `#e09a72` | 警示/计费状态（与 Claude Code mark 赤陶橙 `#d97757` 为不同色值，仅用于状态提示，不用于任何品牌语境） |

辅助色上限即上表的暖黄与警示橙两种；不得再增补插画专用色，需要新状态时复用或走 spec 修订。

### 对比度规则与核算证据（WCAG 2.2 相对亮度法，2026-08-17 核算）

核算底色：浅色模式页面底 `#ffffff`（Starlight 浅色 `--sl-color-black`）；深色模式页面底约 `#17181c`（Starlight 深色 `--sl-color-black: hsl(224,10%,10%)`）。

| 前景/背景组合 | 浅色 | 深色 | 要求 | 结论 |
| --- | --- | --- | --- | --- |
| ink vs 页面底 | 14.76 | 15.86 | 文字 ≥ 4.5，图形 ≥ 3 | 通过 |
| accent vs 页面底 | 4.95 | 10.40 | 图形 ≥ 3（亦满足文字 4.5） | 通过 |
| accent-deep vs 页面底 | 7.52 | 13.46 | 图形 ≥ 3 | 通过 |
| on-accent vs accent 填充 | 4.95 | 10.40 | 文字 ≥ 4.5 | 通过 |
| warn vs 页面底 | 5.48 | 7.63 | 图形 ≥ 3 | 通过 |
| yellow vs 页面底 | 1.38 | 12.82 | 装饰填充，无独立要求 | 见规则 3 |
| ink vs yellow 填充 | 10.67 | —（深色沿用同黄） | 标签文字 ≥ 4.5 | 通过 |
| ink vs fill 填充 | 13.32 | 11.17 | 描边承托 ≥ 3 | 通过 |
| fill vs 页面底 | 1.11 | 1.42 | 装饰填充，无独立要求 | 见规则 3 |

规则（评审按此执行）：

1. **插画内文字只允许 ink 色与 on-accent 色**（accent 填充上的数字/对勾），渲染对比度 ≥ 4.5:1。
2. **形状边界由 ink 描边承托**，描边对页面底 ≥ 3:1；accent、warn 作为填充或线条出现时本身 ≥ 3:1，可独立承托有含义的图形（站点、计费表指针、警示）。
3. **低对比装饰填充（`--xun-fill`、浅色模式下的 `--xun-yellow`）不得单独承载含义**：任何使用它们的形状必须带 ink 描边，且不得作为唯一状态指示（状态另配文字/描边，非颜色单编码）。
4. 深色模式使用同一套 token 自动切换，`--xun-paper` 与页面底一致，避免深底上出现「发白补丁」。

## 三、描边与形态语言

- **描边基准 2.5**（SVG viewBox 单位，默认渲染尺寸下即 2.5px；等比缩放时描边随缩放，缩到 80px 以下不建议再缩小）。允许的偏差：内车道虚线 2、徽章对勾 3（加粗承托含义）、装饰细线不细于 2。
- `stroke-linecap/linejoin: round`；圆角用于角色与舞台，**不**用于正文内容卡片（避免撞上 t03「圆角卡片加左彩边」禁区的观感；插画卡片式元素一律用完整边框，不做左侧单彩边）。
- 无渐变、无阴影、无位图；层次只用「留白底 + 装饰填充 + ink 描边」三层表达。

## 四、排印

- 正文排印不变（Noto Sans SC 16px+，行高 1.7）。
- **插画内文字最小渲染 14px**，且仅限标注（token 标签、站点数字）；实现基准：`Cast` 内 SVG 文字为 12–13 个视图单位，按默认渲染宽度（package 200px / 160 viewBox、track 260px / 220 viewBox）折算为 15–15.4px。**缩小渲染时不得低于 14px 折算线**（package 最小渲染宽度约 187px、track 约 237px；再小则去掉标签文字、由外部 HTML 标注承担）。
- 插画内文字长度预算：package 标签约 10 个半角字符（如 `428 tokens`；运单式挂签 92×24 视图单位、12 号字，2026-08-17 用 Chromium 默认等宽字体实测 10 字符宽约 84 单位，留边约 4 单位/侧）。

## 五、面积预算

- **单课插画元素合计不超过首屏面积的 40%**；教学文字永远是主角。W1–W4 每课只有一个核心可视化（循环跑道/指令小剧场/请求之旅/分岔地图），不做装饰性堆放。
- 角色默认渲染尺寸：小循 120px（讨论区/旁白位可降至 80px，站旁陪伴不低于 64px）；配角 key 160px、package 200px、track 260px。
- 首屏 hero 不放插画角色；插画只出现在课节交互区与进度指示。

## 六、动画、静态等价物与 `prefers-reduced-motion`

- **点击推进，不自动播放**；无音效；无积分/徽章/打卡/排行榜（AGENTS.md 契约）。
- 每个动画组件必须提供**静态等价物**：`<noscript>` 分步文字说明、打印样式下输出当前帧加图注、`prefers-reduced-motion: reduce` 时动画退化为「静态分帧 + 手动『下一帧』按钮」——分帧内容与动画帧一一对应，不是缩略版。角色姿态切换（pose props）天然是静态帧，动画即帧间过渡。
- reduced-motion 下允许保留 ≤ 0.01ms 的过渡归零（仓库现有全局规则已覆盖），不得有循环、平移、缩放类持续动效。
- 禁止用动画呈现「进度条等待」以外的假装载状态；W3 动画回放的必须是真实记录的数字（v3 规格 D4/D5）。

## 七、无障碍：文本替代与 `aria-live` 播报

- 每个角色 SVG 默认 `role="img"` + 中文 `aria-label`（如「小循（疑惑）」「贴 token 标签的包裹（标签：428 tokens）」）；纯装饰用法必须显式 `decorative`（输出 `aria-hidden`）。画布内装饰符号（问号、灯泡）标注 `aria-hidden`，含义进外层图注。
- 每个动画阶段变化必须写入 `aria-live="polite"` 播报区（如「包裹已到达服务商，正在验证钥匙」），播报文案与分帧图注同源，由状态机同一数据驱动，避免两套文案漂移。
- 交互控件（推进按钮、姿态切换）为真实 `<button>`/`<input>`，键盘可达，焦点可见（≥2px outline），hit target ≥ 44×44px；拖拽交互必须提供键盘替代路径（v3 规格第 4 节）。
- 状态不得只靠颜色编码：完成/警示除颜色外必须带对勾、旗、文字等形状或文字线索（本 spec 二节规则 3 的非颜色编码落地）。

## 八、许可证与来源

- 小循与全部配角、场景均为**仓内原创 SVG**：内容资产以 CC BY 4.0 发布，组件代码以 MIT 发布（与仓库整体许可一致）；登记于 `docs/sources/source-ledger.json`（条目 `v3-illustration-cast-original`）。
- 不引入：AI 生成插画、素材站资产、第三方 IP 角色化用或致敬改名；不复刻任何官方产品吉祥物/插画风格（ADR-0009 第 3、4 条）。

## 九、评审与验证入口

- 预览全部姿态与配角（含深浅色并排与色板对比度表）：站内 `/mascot-preview/`（构建产物；页面标注 noindex、不进侧栏）。
- 构建验证：`site/` 下 `npm run build` 与 `npm run test` 全绿。
- 课节接入（V3-3…V3-6）时按本 spec 逐条对照，新增形态或颜色需先修订本文件并回溯 ADR-0009 边界。
