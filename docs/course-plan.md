## 1. 课程定位

这是一门公开、免费、可版本化自学的中文网页课程，面向科研与企业团队中的技术型 Agent 初学者。课程以 Coding Agent 工程实践为主，以 Agent Application 工程解释底层能力并提供进阶路径。

学员不需要预先系统学习 Agent，但应能够使用编辑器和终端，并能阅读少量 Python 或 JavaScript。考虑到不少目标学员没有稳定的 Git 习惯，课程设置“前置技能补给站”，用一个安全、可恢复的最小 Git 工作流建立后续实验基线，而不是把 Git 当作隐含前提。

课程不把 Codex 或 Claude Code 写成功能说明书，也不把二者包装成完全等价的工具。课程先建立厂商无关的 Agent 能力模型，再让 Codex 与 Claude Code 交替承担主实验，另一工具通过差异说明和迁移挑战出现。

## 2. 学习成果与结业线

### 2.1 核心课程结业线

预计学习时间为 20–24 小时。完成后，学员应能：

1. 区分模型、Agent、Agent Harness、Coding Agent 与 Agent Application。
2. 在真实代码仓库中安全使用 Codex 或 Claude Code 完成澄清、计划、修改、验证和交付。
3. 使用仓库级指令文件控制 Agent 的工作边界，并解释规则的作用域与优先级。
4. 诊断上下文污染、遗漏和压缩问题，主动管理上下文预算。
5. 为明确用途设计受控 Memory，并识别不应被持久化的信息。
6. 创建并验证一个自定义 Skill，理解 Skill 与普通提示词、脚本和工具的区别。
7. 接入并审计一个 MCP Server，能说明 Host、Client、Server、Tool、Resource 与 Prompt 的边界。
8. 从 Plugin 的系统视角理解能力打包、发现、安装、版本与供应链风险。
9. 对 Codex 与 Claude Code执行同一能力目标的迁移挑战，并提交可核验成果。
10. 完成科研或企业轨道的核心结课任务。

### 2.2 进阶实战线

预计额外学习时间为 8–12 小时。完成后，学员应能：

1. 使用 Python 和官方模型 API/SDK 手写最小 Agent loop。
2. 明确状态、工具执行、错误恢复和停止条件分别由谁拥有。
3. 加入基础的结构化输出、评测、日志、成本控制和安全边界。
4. 对 OpenAI 与 Anthropic 的实现进行概念级和接口级对照。
5. 将核心结课任务扩展为一个最小 Agent Application。

TypeScript 只作为对照附录；课程先教授可迁移的控制流，再在选修内容中比较 Agents SDK、Claude Agent SDK 与其他框架。

## 3. 课程知识架构

课程由两层共同组成：

- **稳定知识层**：Agent loop、指令、上下文、状态、Memory、工具边界、Skill、Plugin、MCP、编排、验证与安全等跨版本概念。
- **工具适配层**：Codex、Claude Code、模型、SDK、API、安装命令和配置等易变内容，必须标注适用版本、核验日期和变更记录。

核心能力地图按以下顺序组织：

1. 模型与 API
2. 指令与规则
3. 上下文与状态
4. Memory
5. 工具与 MCP
6. Skill 与 Plugin
7. 编排与多 Agent
8. 评测、安全、成本与运维

课程会持续澄清这些容易混淆的边界：

| 概念 | 课程中的工作定义 | 关键区别 |
| --- | --- | --- |
| Prompt | 一次交互中给模型的输入 | 不等于可复用、带资源和流程的 Skill |
| Agent 指令工程 | 明确目标、上下文、约束、工具边界、输出契约和验收标准，并根据证据迭代 | 不教授“万能提示词” |
| Context | 当前推理所能看到的工作集 | 容量有限，会变化和被压缩 |
| Memory | 为后续任务受控保留的信息 | 不是把全部历史对话永久保存 |
| Tool | Agent 可调用的一项外部能力 | 不规定跨进程发现和传输协议 |
| MCP | Host、Client 与 Server 之间交换上下文和能力的开放协议 | 不等于某一个 Tool 或 Plugin 市场 |
| Skill | 围绕特定任务组织的可复用知识、流程与资源 | 不自动等于安装、分发和生命周期系统 |
| Plugin | 对能力进行发现、安装、组合、更新和治理的打包机制 | 可包含 Skill、命令、Hooks 或 MCP 配置，但产品实现不同 |
| Agent Harness | 承载循环、工具、上下文、权限和执行控制的运行外壳 | Codex 与 Claude Code都属于具体 Harness 实现 |
| Agent Application | 用 API、工具、状态和上下文管理构成的目标导向软件 | 不等于现成 Coding Agent 客户端 |

### 4.2 模块 0 的 Git 最小工作流

Git 教学只覆盖后续 Agent 实验真正需要的习惯：

- `clone` / `init`、`status`、`diff`、`add`、`commit`、`branch`、`log`
- `.gitignore` 与密钥排除
- 修改前建立基线，修改后先看 diff，再验证，最后由人决定是否提交
- 恢复工作区的基本方法
- 冲突和 worktree 的风险意识，不展开为完整 Git 系统课

主路径采用 Windows 11 与 PowerShell 7；macOS 和 Linux 差异以清晰标签补充。首版不建设完整云端浏览器 IDE。

### 4.3 Agent 指令工程的教学范围

指令工程模块覆盖目标、上下文、约束、非目标、示例、输出格式、结构化输出、工具描述、验收标准、失败证据、规则冲突、提示注入与过长指令。核心实验让学员对同一真实任务分别使用模糊请求和工程化指令，比较 Agent 的计划、操作、失败模式和验证质量。

课程不提供脱离场景的“万能 Prompt 库”，而是让学员掌握能被观察和复用的指令设计方法。

## 5. 教学与练习设计

### 5.1 统一课节语法

每个实操课节遵循同一节奏：

1. 真实问题
2. 心智模型
3. 操作前预测
4. 主工具演示
5. 本地实验
6. 故障注入与恢复
7. 迁移挑战
8. 可核验成果
9. 风险、版本与来源卡片

每个课节必须让学员留下文件、配置、测试输出、运行证据或提交记录，页面上的“已读”状态不视为学习成果。

### 5.2 交替主讲与迁移挑战

Codex 与 Claude Code 保持同等重要，但不逐步骤制作两套重复课程：

- 每个能力单元由一个工具承担完整主实验。
- 另一工具提供差异说明和迁移挑战。
- 后续模块交换主讲工具，避免形成默认主次关系。
- 迁移挑战改变输入、约束或故障条件，不允许原样复刻。
- 课程明确标出概念相同处、操作差异和暂时无法对齐的产品能力。

### 5.3 渐进式解题支持

答案按以下层级展开：

1. 学员先预测结果。
2. 提供方向提示。
3. 提供诊断提示。
4. 运行本地检查器并查看证据。
5. 最后展示带解释的参考实现。

课程不做防作弊监控；重点是让失败可诊断、结果可验证。

### 5.4 风险与验证卡片

每个实战单元都必须明确：

- 所需账号、成本与最低可用路径
- 权限、外部副作用和人工确认点
- 文件、命令和网络访问范围
- 密钥、个人信息与研究/企业数据边界
- 预期成功证据
- 常见失败和恢复方法
- 工具、模型、SDK 或协议适用版本
- 官方事实、课程判断、实验结果与未核验信息的区分

## 6. 公共练习仓库与结课项目

### 6.1 统一练习主题

公共练习仓库采用合成项目“设备遥测与报告工具”，包含：

- 带缺失值、异常值、单位混乱和时间戳问题的传感器 CSV
- Python 数据验证、统计、绘图和报告生成代码
- CLI、测试、文档、Issues 和版本历史
- 刻意设置的缺陷、冗余文件、过期说明和上下文噪声
- 可由 Codex、Claude Code 和最小 API Agent 处理的同一组任务

项目不使用真实敏感实验或企业数据。每章在同一仓库上增加能力，让上下文、Memory、Skill、MCP 与 API 的价值在长期演化中显现，而不是每章更换玩具 Demo。

### 6.2 科研结课轨道

学员把项目视为可复现科研工作流，完成数据质量检查、分析脚本、图表、实验记录和报告交付。核心版本要求使用 Coding Agent、上下文管理、受控 Memory、自定义 Skill 与 MCP；进阶版本再加入最小 API Agent，自动完成一个边界清楚、可复核的步骤。

### 6.3 企业结课轨道

学员把项目视为软件产品，完成 Issue 澄清、计划、实现、测试、评审和交付说明。核心版本同样要求 Coding Agent、上下文管理、受控 Memory、自定义 Skill 与 MCP；进阶版本加入最小 API Agent，处理一个经过评测和权限约束的 Issue-to-PR 子流程。

两条轨道使用共同评价维度：问题定义、上下文质量、操作安全、验证证据、可复现性、迁移能力和交付清晰度。

## 7. 课程检查器与学习记录

课程提供统一 Python 检查器，典型入口为：

```text
python -m course_check lesson-05
```

检查器只在学员本机运行：

- 检查产物与证据，不要求唯一实现。
- 同时输出人类可读结果和匿名 JSON。
- 不上传源码、密钥或运行数据。
- 既包含已知正确样例，也包含故障样例，以验证检查器不会只接受“标准答案”。
- JSON 可由课程网页主动导入，用于更新本地学习记录。

网页不设置账号、广告、分析脚本或跨设备云同步。学习进度保存在浏览器本地，并支持 JSON 导出和导入。

## 8. 网站信息架构与技术方案

### 8.1 技术选型

网站采用 Astro、Starlight 与 MDX，以静态内容为主体，只为模拟器和本地进度加入少量 React islands。选择这一架构是为了获得内容导航、搜索、代码展示、多语言扩展和静态部署能力，同时保持较低运维和隐私成本。

课程工作区规划为单仓库：

```text
课程工作区
├─ site/       静态课程站、MDX 内容与浏览器交互
├─ labs/       设备遥测练习基线、任务与故障样例
├─ checker/    Python 课程检查器及匿名结果契约
└─ docs/       规划、领域语言、ADR、来源研究与维护记录
```

网站、练习、检查器和版本元数据由同一个 release tag 锁定。部署目标为 GitHub Pages，使用 GitHub Actions 构建和发布；自定义域名延后处理。

### 8.2 首个纵向切片

在批量制作全课前，先交付一个可评审纵向切片：

1. 首页与 Agent 能力地图
2. 模块 0 的 Git 最小工作流
3. 模块 1 的 Agent loop 交互动画
4. 模块 2 的模糊指令/工程指令对照
5. 模块 3 的 Codex/Claude Code双工具任务
6. 上下文预算模拟器
7. 本地公共练习仓库与首个检查器

视觉实现前，使用同一组真实内容制作三种可见、可交互的设计方向，再选择、混合或否决；不凭抽象风格标签直接定稿。

### 8.3 移动端与无障碍

移动端支持完整正文阅读、知识检查、搜索、模拟器和本地进度；终端、Git、Codex、Claude Code、Python 与 MCP 实验明确要求桌面环境。

首版以 WCAG 2.2 AA 为最低目标，覆盖键盘导航、可见焦点、对比度、减少动态效果、非颜色编码、图示文本说明和媒体字幕。纵向切片开始时即验证这些要求，避免在发布前集中补救。

## 9. 课程内容契约

所有正式实操课节使用统一元数据，至少包括：

- 课节 ID、阶段、预计时长与先修关系

- 原创课程正文和图解：CC BY 4.0
- 自有代码、练习脚手架和检查器：MIT
- 第三方资产：保留原许可证，不被项目双许可覆盖

发布前必须完成来源追溯和许可证检查。不能确认许可的资产只做外链发现，不进入课程包。

## 11. 发布、维护与质量门槛

### 11.1 维护节奏

- 每周自动检查链接、依赖和上游发行变化。
- 每月人工复核工具适配层。
- 每季度形成一个课程版本。
- 安装、安全、API 和 MCP 的关键变化随时紧急修订。
- 自动化只报告变化，不盲目改写教学内容。

### 11.2 发布门槛

一个课节进入正式版本前必须满足：

1. 内容契约字段完整。
2. 所有正式实验在 Windows 11 + PowerShell 7 实测。
3. macOS 或 Linux 至少完成一条跨平台复核路径。
4. 不包含明文密钥、危险默认权限、失效命令或不可恢复步骤。
5. 检查器同时通过正确样例和故障样例。
6. 来源、固定版本和许可证可追溯。
7. 工具适配内容人工复核时间不超过 90 天。
8. 关键阅读和交互路径通过无障碍审计。

### 11.3 试学审计与指标

纵向切片邀请 8–12 名代表性初学者试学，尽量覆盖：

- 科研与企业背景
- 有/无稳定 Git 习惯
- 仅能使用 Codex、仅能使用 Claude Code，以及两者都可用

审计记录真实阻塞点、操作观察和可核验结果，不只收集满意度。Alpha 目标指标为：

- 至少 80% 学员完成环境基线。
- 至少 70% 学员产出第一个可核验成果。
- 至少 60% 学员完成双工具迁移挑战。
- 无关键安全、密钥、失效命令或不可恢复问题。

### 11.4 最高层测试接缝

课程以一条端到端学习旅程作为唯一的最高层验收接缝：从一个锁定的课程版本出发，学员能够在 Windows 11 + PowerShell 7 环境中打开课程、完成正式实验、通过 `course_check` 获得匿名 JSON，并将结果导入网页形成可核验完成状态。

验收只观察学员可见行为和证据，不绑定内部实现。内容契约校验、链接与许可证扫描、检查器样例测试及模拟器单元测试属于这条旅程的下层验证器，不另行扩张为彼此竞争的顶层接缝。

## 12. 实施里程碑

### 里程碑 1：Foundation

建立课程内容契约、来源账本、版本元数据、设备遥测练习基线和检查器骨架。目标是先固定可维护的边界与验证方式。

### 里程碑 2：Alpha 纵向切片

实现首页、能力地图、模块 0–3、关键交互、首个本地实验与检查器，并进行 8–12 人试学审计。Alpha 结束后再根据真实制作速度估算后续日期。

### 里程碑 3：Core Beta

完成模块 4–10，覆盖项目指令、上下文、Memory、Skill、Plugin、MCP 与受控多 Agent，并补全科研/企业核心结课路径。

### 里程碑 4：v1

完成模块 11–12、最小 API Agent、生产化内容和双轨进阶结课，完成无障碍、来源、许可、跨平台与安全审计后发布首个正式版本。

## 13. 支持与社区边界

首版使用 GitHub 原生协作面：

- Issues：内容错误、过时信息、无障碍和安全问题
- Discussions：学习问答和成果展示
- Pull Requests：勘误、工具适配和实验改进

首版不承诺 Discord、微信群等实时社区支持。只有安装流程和复杂交互可能补充短视频；所有必要信息必须保留可搜索的文字版本。

## 14. v1 明确不做

- 模型训练、微调和强化学习
- 完整 RAG 或向量数据库平台课程
- 多 Agent 框架系统课
- 无代码 Agent 平台
- 复杂云部署、Kubernetes、SSO 与企业身份治理
- 全量 Codex/Claude Code CLI 参数手册
- Cursor、Copilot、Gemini 等工具的完整并行课程
- 认证考试题库和防作弊系统

这些主题进入“下一步学习地图”，并标注先修关系，不在 v1 内隐性扩张。

## 15. 主要风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 工具和 API 快速变化 | 稳定知识层/工具适配层分离；版本、日期和变更记录进入内容契约 |
| 双工具内容重复或失衡 | 交替主讲 + 迁移挑战；按能力目标验收，不按功能数量平衡 |
| 教程来源过时或带平台偏见 | 官方资料作为事实真源；重点参考集只承担教学参考角色 |
| 命令执行、权限和密钥泄漏 | 每课风险卡片；人工确认点；合成数据；本地检查；发布前安全审计 |
| 第三方许可污染 | 来源账本、固定版本、逐资产许可证检查和双许可边界 |
| Windows 学员被 POSIX 示例阻塞 | Windows 11 + PowerShell 7 作为正式主路径并纳入发布门槛 |
| 学员只会照抄步骤 | 操作前预测、故障恢复、迁移挑战和变化输入 |
| 课程范围失控 | v1 排除清单、四阶段里程碑和纵向切片先行 |
| 网站可读但实验不可做 | 以可核验成果和端到端学习旅程作为验收对象 |
