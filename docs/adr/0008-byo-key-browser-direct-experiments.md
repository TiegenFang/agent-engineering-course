# ADR-0008: 自带密钥实验采用浏览器直连，不部署代理服务

日期：2026-08-17
状态：已接受（维护者于 v2 重定位 grilling 会话拍板）

## 背景

v1.0.0 发布后，维护者反馈课程可交互性不足：学员应当能在网页内理解「什么是 API key」，并输入自己的密钥真实调用模型对话。与此同时，仓库安全契约规定密钥不得进入仓库、日志、截图或任何服务器；ADR-0004 固定了静态内容优先、不引入应用服务器的架构。

## 决定

网页端起步章的模型调用实验采用**自带密钥（BYO-key）+ 浏览器直连**：

- 学员在页面输入自己的 OpenAI 或 Anthropic API 密钥，浏览器 JavaScript 直接 `fetch` 官方 API 端点；密钥只存在于页面内存，刷新即失，不写 `localStorage`，不经过课程任何服务器。
- Anthropic 调用携带官方 CORS 头 `anthropic-dangerous-direct-browser-access: true`（2026-08-17 核验）。
- 实验页必须同时提供**离线演示模式**（默认）：不输密钥、零网络也能完整学习概念，符合分层访问路径的免费要求。
- 页面明示：密钥在本机开发者工具中可见、公共电脑勿用、费用自理、用完可在服务商控制台撤销。

## 备选方案与取舍

- **模拟对话（不接真 API）**：绝对安全但失去真实调用体验，不满足维护者要求，仅保留为离线演示模式。
- **课程站代理服务**：体验最顺（可隐藏密钥、可缓存），但引入应用服务器、滥用防护、成本与运维责任，直接违反 ADR-0004，且课程将代管学员密钥，风险等级反而上升。
- 浏览器直连的代价（密钥暴露在学员本机、无统一计量）由学员自担且页面如实告知；课程不接触密钥，静态架构与隐私契约保持完整。

## 后果

- 「课程不收集密钥」的边界不变：代码评审只需检查组件没有把密钥发往课程域名或持久化。
- 真实调用路径无法在 CI 中验证（无密钥、不产生费用），CI 只验证离线演示模式与契约；真实调用标注为「现场验证项」。
- 若未来浏览器直连被服务商限制，本 ADR 的实现层需重新核验；架构决定本身不变。
